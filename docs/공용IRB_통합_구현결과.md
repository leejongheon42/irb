# 공용 IRB 통합 구현 결과

기준 문서는 `.omo/plans/public-irb-code-gap-plan.md`이다. 자체 IRB로 저장된 기존 과제에는 기존 기준을 적용한다. 공용 IRB 과제는 이용 경로, 연구 분류와 방법, 신청 구분, 복수 동의 경로, 연령과 대리인 동의 여부를 저장하고 공용 제출 요구표를 사용한다.

## 반영한 기능

| 계획 항목 | 구현 결과 |
| --- | --- |
| 원문 등록 | 관리자 화면에서 참고 목록을 등록하고 원본을 업로드할 수 있다. 계열·번호·판본으로 구분하고 SHA-256으로 저장한다. 표지 대조 결과와 검수 기록을 남긴 후 현행판으로 지정한다. |
| 과제별 기준 | 자체·공용 IRB를 구분한다. 제출 당시의 규칙 세트, 요구표, QC 기준 파일과 과제 입력, 첨부 문서, 적용 점검표 정보를 보관한다. |
| 제출 요구표 | 사전검토, 패키지, 과제에 연결된 QC, 제출 이력과 API에 공용 기준을 연결했다. e-IRB 준비·제출·해당 없음 표시를 과제 및 신청 유형별로 저장한다. 공용 변경 신청에는 변경대비표와 변경된 문서를 표시한다. |
| 서식 라이브러리 | 위원회·서류 종류·변형별로 활성 서식을 조회한다. 검수한 공용 원본과 연결한 DOCX/HWPX 파생본을 사용할 수 있다. 검수된 생성용 서식이 없으면 패키지에서 검수된 원본 또는 공용위원회 자료실을 안내한다. |
| 평가점검표 | 원문에서 표 행 초안을 추출하고 관리자 검수 후 항목을 등록한다. 연구자는 자가점검표를, 배정된 사전검토자는 위원회용 항목을 작성한다. 답변·해석·근거 위치·작성자를 기록하고 과제 구성원이 사전검토자로 판정하는 것을 제한한다. |
| 신청 후 업무 | 이탈·이상반응·조기종료·이해상충 변경·정보 제공·검체 제공·폐기 및 이관을 개별 기록한다. 변경 내용을 이미 시행했다는 답변은 이탈 보고로 연결한다. 연구자가 외부 통지서와 결과를 연결할 수 있다. 수정 후 신속심의 상태는 외부 후속 결정을 기다린다. |
| 기한 알림 | 이해상충 변경 인지일에서 30일을 계산한다. 이탈·이상반응은 발생일을 저장하고 기한 확인 알림을 표시한다. 보고 기록을 연결하면 해당 알림을 종료한다. |

## 화면과 API

- 관리자 → **공용 IRB 원문 관리**에서 참고 목록 불러오기, 원본 업로드, 표지 대조와 현행 검수, 점검표 항목 등록을 진행한다. **기관 서식 템플릿** 메뉴에서 공용 파생본을 등록한다.
- 연구자는 과제 작성 화면에서 **공용 IRB**를 선택하고 제출 서류 패키지를 확인한다. 과제 상세의 **공용 IRB 제출 준비 및 평가점검표**에서 e-IRB 입력 상태와 평가표를 볼 수 있다.
- `GET /api/protocols/{id}/requirements`에서 현재 요구표를 조회한다. `kind`로 신청 유형을 고르거나, `submission_id`로 해당 제출의 저장된 기준과 자료를 조회한다.

## 활성화와 복원

- `IRB_PUBLIC_IRB_ENABLED=false`는 신규 공용 과제 선택을 숨긴다. 기존 과제 데이터에는 위원회 기본값 `institution`을 채우고 스키마 적용 이력을 `schema_meta`에 기록한다.
- 운영 반영 전 SQLite 쓰기를 중단하고 데이터 볼륨 전체를 백업한다. DB, 업로드, 원본 저장소, 템플릿 및 키가 같이 있어야 한다. 복구 시 이전 이미지와 백업 볼륨을 같은 시점 기준으로 복원한 후 과제, 첨부, 기동 상태를 확인한다.

## 검증 결과

- 전체 회귀 테스트 225개가 통과했다. 이 중 공용 IRB 추가 검증은 17개다. Ruff 검사도 통과했다.
- HTTP 테스트로 공용 패키지의 권고서식, e-IRB 상태 저장, 현재와 과거 제출의 요구표 API, 다른 연구자의 조회 차단을 확인했다. 평가점검표 테스트에서 연구자의 위원회용 판정 저장 차단과 배정된 사전검토자의 근거 저장을 확인했다.
- 새 Docker 이미지로 별도 SQLite 볼륨에서 서비스를 기동했다. `http://127.0.0.1:8002/api/health`가 `status: ok`를 반환했고 로그인 화면은 HTTP 200으로 응답했다. 기존 8001 인스턴스와는 별도로 실행했다.
- 이전 이미지로 만든 샘플 과제 2건이 포함된 Docker 볼륨을 백업하고 새 이미지로 마이그레이션했다. 두 과제의 자체 IRB 설정과 스키마 이력을 확인했다. 백업을 별도 볼륨에 복원해 이전 이미지에서 기존 스키마와 두 과제가 조회되는 것을 확인했다. 이 과정은 별도 볼륨에서 수행했다.

## 현행 원문 확인이 필요한 범위

- 참고 목록은 출처와 서식 식별 정보를 등록한다. 원본 첨부와 현행판 검수, 실제 점검표 문항 검수, 한글에서 만든 파생본의 표·체크박스·쪽 나눔 대조는 운영 자료가 확보된 뒤 수행해야 한다.
- 협약 기관 조회에서 검수된 XLSX의 기관명이 일치하면 기준일과 기관협약 경로 안내를 표시한다. 원본 XLSX가 등록되기 전에는 조회할 수 없다는 안내를 표시한다.
- 이탈·이상반응의 구체적인 일수는 적용할 SOP 조문이 확인돼야 설정할 수 있다. e-IRB 로그인 화면의 실제 첨부 요건도 확인 대상으로 남겨 두었다.
- 98개 참고 시나리오 중 핵심 요구표 11개를 자동 검증 대상으로 삼았다. 전체 98개 진행 경로에 대한 검증은 남아 있다.
