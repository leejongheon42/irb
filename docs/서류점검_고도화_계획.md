# 서류 자동 검토·보완·점수 평가 고도화 계획

작성일: 2026-11-10 · 대상 코드: `irb_automation/qc`, `package`, `ai`, `doctemplates`, `knowledge`

목표: 연구자가 **서류 초안과 "어떤 IRB인지"에 대한 간단한 설명**만 주면, 시스템이 ① 서류 전체를 평가하고 ② 통과 여부를 판정하고 ③ 보완점을 제안하고 ④ **보완이 반영된 문서**를 돌려주며 ⑤ 문서 간 불일치까지 잡는다.

## 0. 조사 범위와 한계

- 참고 자료: MIRA-Catcher 브로셔 페이지 전체(사용자가 제공한 화면 캡처 6쪽)를 읽고 정리했습니다.
- 브로셔는 제조사 자료입니다. "검토 시간 90% 절감", "서식 보존율 100%"는 측정 방법이 공개되지 않아 목표치로 쓰지 않았습니다.
- 법령 조문은 원문(law.go.kr)을 이번에 대조하지 못했습니다. 3장 G-10 참고.
- 3장의 "실측"은 현재 저장소의 규칙 엔진을 직접 실행한 결과입니다.

## 1. 참고 제품(MIRA-Catcher) 분석

### 1.1 기능 대조

| 브로셔 항목 | 내용 | 현재 시스템 |
|---|---|---|
| 교차 문서 대조 | Protocol + ICF 동시 업로드, 투여 용량·방문 일정·시험 기간·약물명 비교 | 있음. 대상자 수·보관 기간·연구 기간·책임자·제목까지 10항목 |
| 버전 대조 | 파일명 ↔ 본문("v3.0", "Ver 3.0", "버전 3.0", "Version 3.0"), 불일치는 Critical | 있음 |
| 품질 게이트 | 100점, Critical −15 / Major −7 / Minor −2, Critical 1건이면 FAIL | 같음(+ 80점 미만 FAIL) |
| 3단계 스캔 | 규칙(필수항목·버전·용어) → AI 심층(교차 참조·맥락 모순·규제 준수·가독성) → 오탈자·맥락(전문용어·숫자/날짜·문맥 일관성) | 있음 |
| 검증 카테고리 | 10개, "전체 검증" 선택 | 10개. 카테고리 선택 실행은 없음 |
| 입력 형식 | DOCX · HWP · TXT | DOCX · HWPX · HWP · PDF · TXT |
| 자동 교정 | 이슈 선택 → 교정된 DOCX, 변경 부분 색상 표시, 글꼴 통일, 표·머리글·바닥글 유지 | 있음. 추가로 Word 변경 추적본, HWPX 교정 |
| 내용 추가가 필요한 이슈 | **"AI가 대신 쓸 수 없는 영역은 사람이 담당"**: 철회 권리 문구는 사용자가 직접 작성(시나리오 4단계, 10분) | 같음(직접 작성 안내) |
| 재검증 | 수정본을 **다시 업로드**해 73점 FAIL → 96점 PASS 확인 | 수동 재점검. 전후 비교 화면 없음 |
| 보안: Stateless | 검증 후 서버에 문서를 저장하지 않음 | **없음**: 원본·교정본을 `data/qc`에 보관 |
| 보안: 온프레미스 | Docker로 사내 서버 설치, 외부 클라우드 비의존 | 일부: Dockerfile·compose는 있음. AI 단계는 외부 API |
| 보안: 접근 통제 | 사내 이메일 도메인 인증, 관리자 권한 제어 | 계정·역할은 있음. 도메인 제한·SSO 없음 |
| 대상 사용자 | CRO·제약사의 MW, CRA, PM, QA | 병원 연구자 |

### 1.2 "범용 AI 비교"(#vs) 7개 항목으로 본 현재 위치

| 비교 항목 | 브로셔의 주장 | 현재 시스템 | 평가 |
|---|---|---|---|
| 사전 지식 | 문서 유형별 필수항목 DB 내장 | `criteria.yaml` 7개 서류 종류 | 있음. 다만 판정이 키워드 수준(G-1) |
| 교차 문서 검증 | 복수 문서 동시 대조 | 있음 | 추출이 표현에 약함(G-2) |
| 버전 검증 | 파일명 ↔ 본문 | 있음 | 충족 |
| 결과물 | 수정된 DOCX 자동 생성 | 있음 | 충족, 변경 추적본은 우위 |
| 서식 보존 | 표·머리글·바닥글 유지 | 있음 | 충족 |
| 검증 기준 | 동일 기준·동일 결과·점수 | 규칙 단계는 결정론적 | AI 단계 재현성 미검증(G-9, G-11) |
| 보안 | 자체 서버 배포, Stateless | 마스킹 후 외부 전송, 파일 보관 | **가장 큰 열세**(G-14) |

### 1.3 시사점

1. **참고 제품과 기능 뼈대는 동등합니다.** 3단계 스캔, 점수 규칙, 교차·버전 대조, 교정본 생성이 이미 같은 구조입니다.
2. **참고 제품이 하지 않는 것이 이번 목표의 핵심입니다.** 브로셔는 누락된 내용을 사람이 직접 쓰게 합니다. "보완이 반영된 문서를 받는다"는 목표는 참고 제품을 넘어서는 부분이고, 차별점이 됩니다(W11~W13).
3. **참고 제품에는 "어떤 IRB인지"라는 개념이 없습니다.** 임상시험 Protocol·ICF를 전제로 한 도구입니다. 연구 유형별로 기준이 달라지는 병원 IRB 서류에는 프로필 입력(W6~W8)이 따로 필요합니다.
4. **따라잡아야 할 것은 보안과 재검증 흐름입니다.** Stateless 모드, 사내 설치 시 AI 배치, 전후 점수 비교(W15, W17).
5. 브로셔는 Phase 2에 Claude AI를 쓴다고 하면서 외부 클라우드에 의존하지 않는다고 적고 있습니다. 사내 설치 시 AI 단계가 어떻게 동작하는지는 브로셔에 설명이 없습니다. 우리도 같은 문제(AI 배치)를 결정해야 합니다(10장 2번).

## 2. 현재 구현 요약

| 단계 | 구현 | 위치 |
|---|---|---|
| 입력 | 파일 여러 개 + (선택) 기존 과제 선택. 서류 종류는 파일명·본문으로 추정 | `qc/service.py: run_uploads, _guess` |
| 필수 기재사항 | 서류 종류별 키워드/정규식 존재 여부 | `criteria.yaml: required` |
| 값 추출 | 정규식 10종(대상자 수·용량·방문·기간·보관·약물·책임자·제목·연구 기간·자료 기간) | `qc/facts.py` |
| 교차 대조 | 과제 입력값 → 연구계획서 → 다수결 순으로 기준값 결정 | `cross_check` |
| AI 심층 | 전체 문서를 한 번에 1회 호출, 개인정보 마스킹, `fix_old`가 원문에 있을 때만 교정 채택 | `qc/ai_phase.py` |
| 점수 | 건수 × 감점, 80점 미만 또는 Critical ≥ 1 → FAIL | `service.score` |
| 교정 | 문자열 치환만. 누락 항목은 "직접 작성" 안내 | `qc/autofix.py` |
| 초안 | 과제 **입력 필드**의 빈 서술 항목만 채움(문서 자체는 아님) | `package/drafting.py` |

## 3. 격차 분석

| # | 부족한 점 | 근거 | 영향 |
|---|---|---|---|
| G-1 | **필수 기재사항이 키워드 존재 여부로만 판정된다** | 실측: 키워드만 나열한 한 줄짜리 가짜 동의서가 누락 0건으로 통과. `목적`, `위험`, `동의` 한 단어만 있어도 충족 | 내용이 부실해도 PASS. 가장 큰 신뢰도 문제 |
| G-2 | **값 추출이 표현에 약하다** | 실측: "본 연구에는 120명이 참여합니다", "시험군 60명, 대조군 60명", "방문은 여덟 차례", "매일 아침 100mg", "3년이 지나면 폐기" 모두 추출 0건 | 값이 안 뽑히면 교차 대조가 조용히 건너뛰어짐(불일치를 놓치고도 감점 없음) |
| G-3 | **"어떤 IRB인지"를 받는 입구가 없다** | `conditions()`는 과제 레코드가 있어야 동작. 빠른 점검에서 과제를 고르지 않으면 조건 집합이 비어 소아·면제·임상 조건 항목이 전부 생략됨 | 사용자의 핵심 요구(초안 + 간단한 설명)와 불일치 |
| G-4 | **IRB 유형별 기준이 얕다** | `when` 조건 7개뿐. 후향적 차트 리뷰, 의약품/의료기기 임상시험, 인체유래물, 유전체, 설문·면담, AI 학습용 데이터, 다기관 등 유형별 필수 서류·필수 항목 세트가 없음 | 유형과 무관한 지적, 유형 고유 누락 미검출 |
| G-5 | **서류 세트의 완결성을 QC가 보지 않는다** | 필요한 서류 자체가 빠졌는지는 `package` 쪽에만 있고 QC 점수에는 반영 안 됨 | 동의서가 아예 없어도 점수에 영향 없음 |
| G-6 | **기관 양식 대조가 없다** | `qc`는 `doctemplates`를 교정 엔진으로만 사용. 초안의 항목 구성·순서를 기관 서식과 비교하지 않음 | "양식을 보고 잘못된 부분 체크" 요구 미충족 |
| G-7 | **내용 보완을 써 주지 않는다** | `check_required`의 권고문: "자동 교정 대상이 아니며 직접 작성해야 합니다" | "개선된 버전 제공" 요구의 절반만 충족(치환만 가능) |
| G-8 | **점수가 건수에 선형이고 상한이 없다** | 실측: Minor 60건 → 0점. 같은 오탈자 유형 반복, 한 원인에서 파생된 이슈가 중복 감점. 서류별·영역별 점수 없음, 추출 실패(점검 불가)와 통과를 구분 못 함 | 점수가 "IRB 통과 가능성"을 대변하지 못함 |
| G-9 | **AI 단계가 단발 호출이고 검증이 약하다** | 1회 호출, 60만 자 초과 시 통째로 건너뜀, `evidence` 인용이 실제 원문에 있는지 확인 안 함(`fix_old`만 확인), 재현성 장치 없음 | 환각 지적이 Critical로 들어오면 그대로 FAIL |
| G-10 | **법적 근거 표기 검증 필요** | `criteria.yaml` 머리말이 "시행규칙 별지 제34호(인간대상연구 동의서)"라고 적고 있으나, 검색 결과 별지 제34호는 **인체유래물 연구 동의서**(법 제37조)로 보임 | 근거 조문이 틀리면 도구 전체의 신뢰가 떨어짐 |
| G-11 | **성능을 측정한 적이 없다** | 테스트 12건은 동작 확인용. 검출률·오탐률을 재는 정답 세트 없음 | 개선 여부를 판단할 기준이 없음 |
| G-12 | **보완 전후 비교가 없다** | 교정 후 "다시 점검"은 수동, 점수 변화·해소된 이슈 대비표 없음 | 개선 효과를 보여 주지 못함 |
| G-13 | **형식 제한** | PDF·HWP(5.0)는 교정 불가, 스캔본은 점검 불가, 표 구조(방문 일정표 등)는 평문으로만 읽음 | 실제 병원 서류(HWP 다수)에서 효용 감소 |
| G-14 | **보안 통제가 마스킹에 집중** | 전송 전 마스킹·전송 기록은 있음. 업로드 문서 내 지시문(간접 프롬프트 주입) 방어, 점검 파일 보존 기한·자동 삭제, 저장 암호화, 기관 내 모델 전환 옵션은 없음 | 미공개 연구계획(영업비밀·환자 정보)을 다루는 도구로서 부족 |

## 4. 목표 프로세스

```
[입력] 서류 초안(여러 개) + "어떤 IRB인지" 한두 문장 또는 5문항
   │
 ① 연구 프로필 확정 ─ 설명문·서류에서 연구 유형/중재 여부/자료 종류/동의 방식/취약 대상/다기관을 추출
   │                  → 사용자에게 1화면으로 확인받음(틀리면 수정)  → 예상 심의 유형(면제·신속·정규)
 ② 서류 분류·구조 분석 ─ 종류 판별, 절(섹션)·표 단위 분해, 필요한 서류 세트 대비 빠진 서류
   │
 ③ 양식 대조 ─ 기관 서식(없으면 표준 항목 구성)과 절 구성 비교: 빠진 절, 빈 절, 순서
   │
 ④ 항목별 평가 ─ 규칙(결정론) + AI 루브릭: 항목마다 충족/부분/미흡/해당 없음 + 원문 인용 + 근거 조문
   │
 ⑤ 연구 사실표 ─ 서류별로 같은 스키마로 값 추출(정규식 + AI) → 문서 × 항목 대조표 → 불일치
   │
 ⑥ 판정 ─ 영역별·서류별 점수, 통과/조건부/미통과, 점검하지 못한 항목 명시
   │
 ⑦ 보완본 작성 ─ (a) 치환 (b) 표준 문안 삽입 (c) AI 문안 삽입·재작성 → 변경 추적본 + 보완 요약표
   │
 ⑧ 재점검 ─ 보완본을 같은 기준으로 다시 점검, 전후 점수와 남은 과제 표시
```

원칙
- **규칙이 판정하고, AI는 찾고 쓴다.** 통과 여부를 뒤집는 Critical은 원문 인용이 실제로 확인된 것만 인정한다.
- **모든 지적에 위치와 근거**(서류·절·인용 문장·조문/지침)를 붙인다.
- **AI가 쓴 문장은 항상 변경 추적으로** 넣고, 연구자가 수락해야 최종본이 된다. 지어낼 수 없는 정보는 `[확인 필요: …]`로 남긴다(현재 `drafting.py` 방식 유지).
- 시스템의 판정은 제출 전 자가 점검이며 IRB 심의 결과를 보장하지 않는다는 점을 결과 화면에 명시한다.

## 5. 작업 계획

### 1단계: 판정 신뢰도 (가장 먼저)

| 작업 | 내용 | 주요 파일 |
|---|---|---|
| W1 정답 세트·평가 도구 | 정상 서류에 오류를 심은 합성 세트(유형별 30~50건: 수치 불일치, 누락, 자기모순, 버전, 용어) + 실제 보완 요청 사례. 검출률·오탐률·교정 정확도·재현성(같은 입력 3회)을 재는 `python -m irb_automation qc-eval` | `tests/qc_eval/`, `qc/eval.py`(신규), `qc/samples.py` 확장 |
| W2 필수 항목 판정 강화 | 키워드를 "후보 위치 찾기"로 낮추고, 절 단위로 **충족/부분/미흡** 판정. 규칙: 최소 분량·필수 요소(예: 철회 = 방법 + 불이익 없음). AI: 항목별 루브릭 평가 + 인용 | `qc/checks.py`, `criteria.yaml`(항목에 `rubric`, `min_chars`, `basis` 추가), `qc/ai_phase.py` |
| W3 사실 추출 2중화 | 정규식 확장(군별 합계, 한글 수사, 표 셀) + AI 구조화 추출(서류마다 같은 스키마, 값마다 원문 인용). 두 결과가 다르면 "확인 필요". **추출 실패를 '미점검'으로 표시** | `qc/facts.py`, `qc/extract_ai.py`(신규) |
| W4 AI 지적 검증 | `evidence` 인용이 원문에 없으면 폐기 또는 강등, Critical은 2차 검증 호출(반박 검토) 통과 시에만 유지. 분량이 크면 건너뛰지 않고 서류 쌍 단위로 분할 | `qc/ai_phase.py` |
| W5 근거 조문 검수 | `criteria.yaml`의 모든 항목에 `basis`(법령·지침 조항) 필드, 별지 서식 번호 등 원문 대조. 연구지원·법무 검토 목록 작성 | `criteria.yaml`, `docs/서류점검.md` |

## 6. 점수 설계안

현재: `100 − 15×C − 7×M − 2×m`, 80점 미만 또는 Critical ≥ 1이면 FAIL.

| 변경 | 내용 | 이유 |
|---|---|---|
| 영역별 점수 | 필수 기재(35) · 문서 간 일치(25) · 규제·윤리(20) · 형식·버전(10) · 표현·가독성(10). 영역 안에서만 감점하고 영역 하한 0 | Minor 누적으로 0점이 되는 문제 해소, 어디가 약한지 표시 |
| 중복 묶기 | 같은 원인(같은 code + 같은 값)은 1건으로, 반복 횟수는 표시만 | 한 가지 실수의 다중 감점 방지 |
| 3단계 판정 | **제출 가능**(Critical 0, 85점 이상) / **보완 후 제출**(Critical 0, 85점 미만 또는 Major 다수) / **제출 보류**(Critical ≥ 1 또는 필수 서류 누락) | PASS/FAIL보다 행동 지침이 분명함 |
| 점검 범위 표시 | 점검 항목 중 실제 판정한 비율. 추출 실패·AI 꺼짐·스캔본은 "미점검"으로 따로 표시하고, 범위가 낮으면 '제출 가능' 판정을 내리지 않음 | 못 본 것을 통과로 오해하는 문제 방지 |
| 확신도 | 규칙 확정 / AI 지적(인용 확인) / AI 지적(미확인). 미확인은 감점하지 않고 "검토 권고"로 | 환각이 판정을 좌우하지 않게 함 |
| 서류별 점수 | 서류마다 소계 | 어느 서류를 고칠지 바로 보임 |
| 보정 | 가중치·기준점은 W1 정답 세트와 W18 실제 결과로 조정. 그 전에는 "잠정 기준"으로 표기 | 80점·15점은 현재 근거 없는 값 |

## 8. 검증 방법

| 지표 | 정의 | 잠정 목표 |
|---|---|---|
| 심은 오류 검출률 | 정답 세트의 오류 중 찾아낸 비율(Critical/Major 별도) | Critical 95% 이상 |
| 오탐률 | 지적 중 실제 문제가 아닌 비율(정상 서류 세트 포함) | 10% 이하 |
| 교정 정확도 | 적용한 교정 중 옳은 비율 | 치환 99%, 삽입 문안은 사람 평가 |
| 재현성 | 같은 입력 3회 실행 시 판정·Critical 집합 일치율 | 판정 100% |
| 실제 보완 요청 적중 | IRB가 실제로 지적한 항목 중 사전에 잡은 비율 | 추세로 관리 |

## 10. 결정이 필요한 사항

1. **대상 IRB 유형의 우선순위**: 후향적 자료 연구부터 할지, 임상시험(의약품·의료기기)까지 처음부터 포함할지. W7의 분량을 좌우합니다.
2. **AI 배치**: 외부 API를 계속 쓸지, 기관 내 모델도 지원해야 하는지.
3. **정답 세트용 실제 서류**: 비식별된 실제 보완 요청 사례와 서류를 제공받을 수 있는지. 없으면 합성 세트만으로 시작합니다.
4. **기준 병원 양식**: 특정 병원 서식을 기준으로 할지, 표준 항목 구성으로 시작할지.
