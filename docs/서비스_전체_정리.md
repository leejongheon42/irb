# IRB 제출서류 자동완성 서비스 전체 정리

기준: 2026-11-15 작업 트리(v4.0 연구자용 + 서류 점검 고도화 + 공용 IRB 통합, 일부 미커밋).
화면 주소별 안내는 [기능_및_화면_안내.md](기능_및_화면_안내.md), 운영 절차는 [운영가이드.md](운영가이드.md)에 있다. 이 문서는 서비스가 무엇을 하고 각 기능이 내부에서 어떻게 동작하는지를 한 곳에 모은다.

## 1. 서비스 개요

병원 의료데이터(EMR·CDW·PACS 등)를 쓰는 연구자가 IRB에 낼 서류를 자동으로 작성하고, 제출 전에 서류끼리 대조해 문제를 찾아 고치는 웹 도구다.

- **심의는 이 서비스에서 하지 않는다.** 심의는 병원 e-IRB나 공용 e-IRB에서 진행되고, 연구자가 통지서를 보고 결과를 옮겨 적는다.
- **맡는 범위는 연구자 쪽 준비 작업이다.** 과제 정보 입력, 서류 작성, 점검과 교정, 제출 기록, 보완 대응, 승인 후 보고 관리.
- **AI 없이도 끝까지 동작한다.** 모든 기능에 규칙 기반 경로가 있고, AI(Claude)는 켰을 때 초안·심층 점검·문서 인식의 품질을 올린다. 기본값은 꺼짐이다.
- **위원회 기준은 과제마다 고른다.** 자체(기관) IRB가 기본이고, 공용 IRB를 선택하면 공용 요구표와 권고서식을 쓴다.

### 전체 흐름

```
① 과제 정보 입력  또는  기존 계획서 업로드 → 항목 자동 추출
② 사전점검: 예상 심의유형 · 위험도 · 동의면제 요건 · 필요 서류
③ 제출 서류 패키지: 빈 항목 초안 → 서류 자동 작성 → 품질 점검 → 자동 교정
④ e-IRB 업로드용 ZIP 내려받기 → 외부 e-IRB에 제출 → 제출 기록
⑤ 결과 입력(승인·시정승인·면제·부결)  또는  보완 요청 붙여넣기 → 답변 초안 → 재제출
⑥ 승인 후: 변경 · 지속심의 · 종료보고 · 이탈/이상반응 등 병행 보고 · 만료 알림
```

## 2. 사용자 역할

| 역할 | 하는 일 | 못 하는 일 |
|---|---|---|
| 연구자 | 과제 생성·수정, 서류 작성·점검·교정, 제출 기록, 결과 입력, 보완 대응, 자가점검표 작성 | 다른 연구자 과제 열람, 위원회용 평가점검표 판정 |
| 사전검토자 | 배정된 과제 열람, 위원회용 평가점검표 항목 판정과 근거 기록 | 과제·문서 수정, 외부 결과 입력. 자신이 연구진인 과제는 판정 불가 |
| 관리자(연구지원) | 기관 프로필·양식·서식, 점검 기준, 지식, 공용 IRB 원문, 사용자 관리, 전체 과제 열람, 감사 로그 | — |

과제 구성원은 연구책임자와 공동연구자다. 과제 열람은 구성원·관리자·배정된 사전검토자만 할 수 있다.

## 3. 기능과 동작 방식

### 3.1 과제 관리와 진행 상태 (`workflow/`, `models.py`)

과제(Protocol) 하나에 제출 기록(Submission)이 쌓인다.

**과제 상태**

```
작성중 ─제출 기록→ IRB 제출함 ─결과 입력→ 승인 / 심의면제 ─┬→ 변경 준비중 ─제출 기록→ …
   ▲                  │                                   ├→ 지속심의 → 승인(기간 연장)
   └─ 보완요청 받음 ◀──┘ (보완 요청 입력)                   └→ 종료보고 → 종료
                                          부결 · 만료
```

**제출 종류 12가지**

| 구분 | 종류 | 과제 상태 변화 |
|---|---|---|
| 주 경로 | 신규심의, 보완 재제출, 변경심의, 지속심의, 종료보고 | 제출하면 "IRB 제출함"으로 바뀐다 |
| 병행 보고 | 위반·이탈, 이상반응, 조기종료, 이해상충 변경, 정보 제공, 검체 제공, 폐기·이관 | 과제 상태를 유지한 채 따로 기록한다 |

**동작**

- 제출 기록 시 과제 내용을 스냅숏으로 저장하고 사전점검을 실행해 함께 남긴다. 필수 보완 사항이 남아 있으면 "보완 없이 기록"을 골라야 기록된다.
- 결과 입력 시 승인이면 승인일과 만료일을 설정한다. 만료일을 비우면 기본 승인 기간(365일)을 더하되 연구 종료일을 넘지 않게 한다.
- 변경심의가 부결되면 마지막 승인 스냅숏으로 과제 내용을 되돌린다.
- 변경을 시작할 때 "이미 시행했는가"를 묻고, 그렇다면 변경심의가 아닌 이탈 보고로 보낸다.
- 공용 IRB 과제는 결과에 "수정 후 신속심의"를 입력할 수 있고, 이 상태는 승인으로 넘어가지 않는다.
- 결과에 외부 통지서(결과통지서·면제확인서) 문서를 연결할 수 있다. 이 두 서류는 업로드만 되고 자동 작성 대상이 아니다.
- 스케줄러가 주기적으로 승인 만료를 처리하고, 만료 60·30·7일 전과 병행 보고 기한에 알림을 보낸다.

### 3.2 IRB 사전점검 (`engine/`, `rules/default_ruleset.yaml`)

과제 입력값만으로 계산하는 규칙 엔진이다. 같은 입력이면 항상 같은 결과가 나온다.

| 단계 | 하는 일 |
|---|---|
| 위험도 | 식별자·민감정보·취약 대상·외부 반출·결합 등에 가중치를 더해 점수와 등급을 낸다. 어떤 요인이 몇 점 기여했는지 함께 보여 준다 |
| 심의유형 | 면제 요건(생명윤리법 제15조제2항)에 맞으면 심의면제, 최소위험 이하면 신속심의, 점수 초과나 고위험 조합이면 정규심의로 분류한다 |
| 동의면제 | 서면동의 면제의 두 요건(제16조제3항)을 각각 평가한다 |
| 필요 서류 | 조건에 따라 제출할 서류 목록을 만든다 |
| 검토 의견 | critical(제출 불가) · major(보완 필요) · minor(권고) · info로 나눠 낸다 |

- 규칙은 YAML 파일 하나에 있고 기관이 사본을 고쳐 쓴다. 저장하면 다음 실행부터 반영된다.
- 결과마다 `버전#해시`를 기록한다.
- 결과는 권고다. 최종 심의유형과 승인 여부는 IRB가 정한다.

### 3.3 제출 서류 패키지 (`package/`, `documents.py`)

이번 제출에 필요한 서류를 정하고, 만들고, 점검하고, 묶는다.

**필요 서류 목록**: 서류마다 준비 방법(자동 작성 / 웹 서식 / 직접 올리기), 현행본, 점검 결과, 갱신 필요 여부를 보여 준다. 과제 정보가 서류 작성 이후에 바뀌었으면 "갱신 필요"로 표시한다.

**한 번에 자동 완성**은 세 단계를 차례로 실행한다.

1. **빈 서술 항목 초안**: 대상자 수 근거, 보안 대책, 보관·파기, 동의면제 사유 등. 입력한 선택값으로 표준 문안을 만들고, AI를 켜면 과제 맥락에 맞게 쓴다. 이미 내용이 있는 항목은 건드리지 않는다.
2. **서류 자동 작성**: 기관 서식이 활성화돼 있으면 그 서식에 채우고, 없으면 내장 서식을 DOCX로 만든다(LibreOffice 필요, 없으면 HTML).
3. **전체 품질 점검**: 3.4의 점검을 과제 서류 전체에 실행한다.

서류 하나가 실패해도 나머지는 계속 진행한다.

**자동 작성 서류**: 심의의뢰서, 연구계획서, 설명문 및 동의서, 동의면제 사유서, 심의면제 확인 신청서, 가명처리 계획서, 증례기록서·자료수집 항목표, 보안 서약서, 변경 대비표, 참여기관 목록, 보완 답변서.

**직접 올리는 서류**: 이력서, 교육 이수증, 타기관 IRB 승인서, 자료 제공 계약서, 예산서.

**e-IRB 업로드용 ZIP**: `01_연구계획서_v2.docx`처럼 번호·서류명·버전으로 이름을 붙이고, 제출 서류 목록과 점검 요약 텍스트를 넣는다.

### 3.4 서류 품질 점검과 자동 교정 (`qc/`)

과제 서류 전체 또는 과제 없이 올린 파일을 점검한다. 상세 기준은 [서류점검.md](서류점검.md)에 있다.

**3단계 스캔**

| 단계 | 방식 | 점검 내용 |
|---|---|---|
| 1 규칙 | 결정론적 | 필수 기재사항, 버전, 미기입·자리표시자, 실제 개인정보, 규제(보관 기간 등), 용어 통일, 교차 문서 대조, 과제 정보 대조, 제출 묶음 구성 |
| 2 AI(선택) | Claude, 개인정보 마스킹 후 전송 | 문맥 모순, 위험 설명 축소, 규제 비준수, 가독성. 1단계에서 찾은 이슈는 다시 지적하지 않는다 |
| 3 오탈자·숫자 | 결정론적 | 오탈자 사전, 단어 반복, 없는 날짜, 기간 역전, 한 문서 안의 표기 불일치 |

**동작 순서**

1. 파일에서 본문·머리글·바닥글 텍스트를 뽑고 서류 종류를 판별한다.
2. 신청 조건 프로필을 만든다. 위원회, 연구 유형, 동의 경로, 취약 대상 등을 기본값·문서·과제 기록·사용자 답변 순으로 채우고 각 값의 출처를 남긴다.
3. 본문에서 값(대상자 수, 용량, 방문 횟수, 기간, 버전, 제목 등)을 추출한다.
4. 같은 종류의 값끼리만 대조한다. 기준 문서를 미리 정하지 않고, 사용자가 기준값을 고른 뒤에만 교정안을 만든다.
5. 같은 불일치에 대한 여러 근거를 하나의 이슈로 묶는다.
6. 점수를 계산한다.

**판정**

- 100점에서 Critical −15, Major −7, Minor −2.
- 검토자가 확정한 이슈만 감점한다. AI 후보와 확인 필요 항목은 감점하지 않는다.
- 확정 Critical이 있으면 FAIL, 확인할 항목이 남으면 HOLD, 그 외 REVISE → MINOR → PASS.
- AI 지적은 인용문이 원문에 실제로 있는지 대조하고, 없으면 "인용 미확인"으로 감점에서 뺀다.

**자동 교정**

| 형식 | 결과물 |
|---|---|
| DOCX | 변경 추적본(Word에서 수락·거부)과 수정 완료본(고친 곳 형광펜). 표·머리글·바닥글 유지, 글꼴 통일 선택 |
| HWPX | 문단 안 텍스트만 교체. 변경 추적 없음 |
| PDF · 구형 HWP | 교정 불가. 원본 DOCX·HWPX를 올려야 한다 |

과제 서류에 적용하면 수정 완료본이 새 버전으로 저장된다. 내용을 새로 써야 하는 누락 항목은 자동으로 쓰지 않는다.

점검 기록은 Word 보고서로 내보낼 수 있다. `qc-eval` 명령으로 추출·판정 회귀 세트를 반복 평가한다.

### 3.5 보완 요청 대응 (`package/revision.py`)

1. IRB 보완 요청문을 붙여넣으면 번호·글머리 기준으로 항목을 나눈다.
2. 항목마다 답변 초안(표준 문안 또는 AI), 고칠 서류와 과제 항목, 관련 법령·가이드를 보여 준다.
3. 보완 답변서(보완 대비표)를 자동 작성해 첨부한다.
4. 재제출 패키지를 점검하고 재제출을 기록한다. 답변이 비어 있는 항목이 있으면 기록을 막는다.

### 3.6 서류함 (`submission/`)

- **업로드 검증**: 확장자와 실제 내용이 다르면 거부한다. 실행 파일, 매크로, 압축 폭탄 의심 파일, 암호 걸린 PDF를 걸러낸다.
- **버전**: 같은 종류의 새 파일을 올리면 이전 것은 "이전 버전"이 되고 새 파일이 현행본이 된다.
- **미리보기**: PDF·이미지는 그대로, DOCX·HWP·HWPX는 PDF로 바꿔 보여 준다. 변환이 안 되면 추출 텍스트를 보여 준다.
- **비교**: 두 버전의 본문을 줄 단위로 비교한다.
- **합본**: 표지·목차를 붙인 PDF 합본과 ZIP을 만든다.
- 파일을 저장하면 3.7의 문서 분석이 자동으로 시작된다.

### 3.7 문서 인식 파이프라인 (`docproc/`, `pipeline/`)

다른 병원 양식의 기존 계획서를 올려 새 과제 초안을 만들거나, 올린 서류를 자동 분석한다. 상세는 [AI_문서자동화_파이프라인.md](AI_문서자동화_파이프라인.md)에 있다.

| # | 단계 | 내용 |
|---|---|---|
| 1 | 문서 인식 | PDF 텍스트층, DOCX·HWPX(XML), HWP 5.x(바이너리 레코드), XLSX, TXT. 스캔본은 AI를 켰을 때만 OCR |
| 2 | 서류 분류 | 키워드·제목·파일명 점수. 올린 종류와 다르면 경고 |
| 3 | 개인정보 점검 | 주민번호·전화·이메일·주소 등 |
| 4 | 정보 추출 | 제목 별칭 사전과 번호 체계로 항목을 찾고 날짜·숫자를 정규화한다. 항목마다 신뢰도와 근거 문장을 붙인다 |
| 5 | 형식 변환 | 마크다운, PDF |
| 6 | 정합성 점검 | 과제 입력값과 문서 값 비교 |
| 7 | 사전검토 | 3.2의 규칙 엔진 |
| 8 | 관련 정보 검색 | 3.10의 지식 검색 |
| 9 | AI 요약 | AI를 켰을 때만 |
| 10 | 서식 작성 제안 | 가져오기에서만 |

- 요청이 끝난 뒤 백그라운드 스레드에서 실행하고 화면이 진행 상태를 주기적으로 확인한다.
- 한 단계가 실패해도 다음 단계는 가능한 범위에서 계속한다.
- 추출 결과는 연구자가 항목별로 골라 과제에 반영한다(빈 칸만 채우기 또는 덮어쓰기).

### 3.8 기관 서식 템플릿 (`doctemplates/`)

병원 고유 서식 파일에 과제 정보를 채운다. 상세는 [기관서식_템플릿.md](기관서식_템플릿.md)에 있다.

1. 관리자가 `{{연구제목}}` 같은 자리표시자를 넣은 DOCX·HWPX를 올린다.
2. 자리표시자를 자동으로 찾아 과제 필드에 연결한다. 목록과 조건 표시도 지원한다.
3. 연결하지 않은 자리표시자가 있으면 활성화할 수 없다.
4. 활성 서식은 위원회·서류 종류·변형별로 하나다. 새 버전을 올려도 이전 버전은 이력으로 남는다.
5. 서명란처럼 사람이 채울 곳은 "그대로 둠"으로 남긴다.

구형 HWP는 채울 수 없다. 한글에서 HWPX로 저장해 올려야 한다.

### 3.9 기관 양식 (`forms/`)

상세는 [기관양식.md](기관양식.md)에 있다.

- **기관 프로필**: 기관명, IRB 명칭·연락처, 과제번호 형식(`IRB-{YYYY}-{SEQ:4}` 등).
- **신청서 추가 항목**: 병원 신청서에만 있는 항목을 YAML 스키마로 정의한다. 조건부 표시를 지원한다.
- **웹 작성 서식**: 이해상충 공개서·서약서처럼 연구진이 각자 작성하는 서식. 제출하면 비밀번호 재입력으로 전자서명하고 서류함에 첨부된다.
- **양식 팩**: 프로필과 양식 묶음을 YAML로 내보내고 가져온다.

### 3.10 관련 규정·사례 검색 (`knowledge/`)

상세는 [관련정보검색.md](관련정보검색.md)에 있다.

- **자료**: 내장 법령·지침·FAQ·보완 가이드, 기관이 올린 SOP, 과거 과제와 IRB 결과·보완 요청.
- **검색 방식**: 형태소 분석기 없이 한글 2글자 단위로 색인하고 BM25로 순위를 매긴다. "제28조의2" 같은 조문 표기는 변형을 같은 토큰으로 맞춘다.
- **질의응답**: 검색된 근거를 인용해 답한다. AI가 꺼져 있으면 근거 문장을 뽑아 보여 준다.
- **노출 범위**: 법령·지침은 모든 사용자, 과거 사례는 자신이 볼 수 있는 과제 것만. 다른 과제는 존재 여부도 보이지 않는다.
- 사전점검의 검토 의견마다 관련 근거를 붙이고, 유사 과제를 보여 준다.

### 3.11 가명처리 도구 (`deid/`)

연구용 추출 자료(CSV)를 가명처리하고 처리 보고서를 만든다.

1. **탐지**: 헤더명과 값 패턴으로 컬럼을 직접식별자·준식별자·민감속성·자유기술로 분류하고 처리 기법을 권고한다. 화면에는 마스킹한 예시만 보인다.
2. **처리**: 삭제, 가명(키 기반 일방향 변환), 마스킹, 범주화(나이 구간·날짜 연월·주소 시군구), 날짜 이동(대상자별 같은 간격), 라운딩, 상·하단 코딩, 자유기술 내 개인정보 제거.
3. **위험 평가**: k-익명성과 l-다양성을 계산하고, k 미만 레코드 비율이 기준을 넘으면 부적정으로 판정한다.
4. **보고서**: 가명처리 계획서의 근거로 쓴다.

가명처리 키는 세션 키와 따로 보관한다. 원본 의료데이터는 AI로 보내지 않는다.

### 3.12 대상자 수 사전 조회 (`feasibility.py`)

연구 설계 단계에서 조건에 맞는 대상자 규모를 본다.

- 집계 건수만 준다. 작은 수는 "<최소셀"로 가리고 나머지는 반올림한다.
- 사용자별 일일 조회 한도가 있고 모든 조회를 기록한다. 조건을 조금씩 바꿔 개인을 추정하는 시도를 막기 위해서다.
- 병원 CDW(OMOP CDM)에 연결하거나, 설정이 없으면 합성 데이터 CSV를 쓴다.

### 3.13 공용 IRB 지원 (`public_irb/`)

과제에서 위원회를 공용 IRB로 고르면 적용된다. 구현 범위와 검증 결과는 [공용IRB_통합_구현결과.md](공용IRB_통합_구현결과.md)에 있다.

| 기능 | 동작 |
|---|---|
| 원문 관리 | 관리자가 공식 서식 원본을 올린다. 계열(권고서식·별지 등)·번호·판본으로 구분하고 SHA-256으로 저장한다. 표지 문구를 추출해 입력한 번호·판본과 대조하고, 사람이 검수한 뒤에만 현행판으로 지정한다 |
| 과제 기준 | 이용 경로(기관협약·개인연구자·기관장 합의), 연구 분류와 방법, 신청 구분, 복수 동의 경로, 대상자 연령, 대리인 동의 여부를 저장한다 |
| 제출 요구표 | 공용 요구표 하나를 사전점검·패키지·QC·제출 이력·API가 함께 쓴다. 항목마다 필수/조건부/증빙/e-IRB 입력 구분과 근거가 있다 |
| e-IRB 입력 상태 | 외부 화면에서 입력하는 항목은 준비됨·제출함·해당 없음을 과제와 신청 유형별로 저장한다 |
| 서식 선택 | 연구 방법에 따라 권고서식(38·39·40·41·43호 등)을 안내한다. 검수된 생성용 서식이 없으면 내장 서식으로 내려가지 않고 원본이나 공용위원회 자료실을 안내한다 |
| 평가점검표 | 원문 표에서 항목 초안을 뽑고 관리자가 검수해 등록한다. 연구자는 자가점검표, 배정된 사전검토자는 위원회용 항목을 작성한다. 답변·해석·근거 위치·작성자를 남긴다. QC 점수와는 따로 기록한다 |
| 기준 고정 | 제출 시 규칙 세트·요구표·QC 기준 파일의 본문과 과제 입력·첨부·점검표 정보를 보관해 나중에 같은 기준으로 다시 볼 수 있다 |
| 보고 기한 | 이해상충 변경은 인지일부터 30일을 계산한다. 이탈·이상반응은 발생일을 저장하고 기한 확인 알림을 낸다 |
| 협약 기관 조회 | 검수된 협약 기관 목록에 소속 기관이 있으면 기관협약 경로를 안내한다 |

`IRB_PUBLIC_IRB_ENABLED=false`로 두면 새 과제에서 공용 선택지가 나오지 않는다. 기존 과제는 모두 자체 IRB로 남는다.

## 4. AI 사용 방식 (`ai/`)

AI를 쓰는 곳: 서술 항목 초안, 서류 심층 점검, 문서 OCR·분류·추출·요약, 보완 답변 초안, 지식 질의응답, 사전검토 보조.

- 모든 호출은 `ai/client.py` 하나를 거친다. 모델은 `IRB_AI_MODEL`(기본 `claude-opus-5-5`)이다.
- AI가 꺼져 있거나 호출이 실패하면 규칙 기반 경로로 계속 진행한다.
- 텍스트는 주민번호·전화·이메일·주소·이름 패턴을 마스킹한 뒤 보낸다. 연구 기간 같은 날짜는 남긴다.
- 원본 PDF·이미지는 허용된 서류 종류(기본: 계획서·의뢰서·증례기록서·가명처리 계획서)이고 개인정보가 탐지되지 않을 때만 보낸다.
- 전송할 때마다 목적·해시·크기·마스킹 건수를 감사 로그에 남긴다. 내용은 남기지 않는다.
- AI 결과는 참고용이며 자동 결정에 쓰지 않는다.

## 8. 한계와 운영 전 확인 사항

- **심의 판단을 대신하지 않는다.** 사전점검·점검표·QC 점수는 모두 내부 참고 자료이고 공식 결과는 외부 IRB 통지다.
- **기준 파일은 기본값이다.** 사전점검 규칙과 점검 기준은 기관 SOP와 대조해 고쳐야 한다. 공용 요구표의 근거는 원문 검수 전이다.
- **공용 IRB 원문은 아직 올라가 있지 않다.** 원본 첨부, 현행판 검수, 점검표 문항 검수, HWPX 파생본의 표·체크박스 대조는 운영 자료를 확보한 뒤 해야 한다. 98개 참고 시나리오 중 자동 검증은 핵심 11개만 있다.
- **이탈·이상반응 보고 기한 일수**는 적용할 SOP 조문을 확인한 뒤 설정해야 한다.
- **스캔본은 AI 없이 읽지 못한다.** 로컬 OCR이 없다. 배포용·암호 HWP는 미리보기 텍스트만 읽는다.
- **값 추출은 일반적인 한국어 표현 패턴 기준이다.** 표현이 특이하면 놓칠 수 있다.
- **백그라운드 분석은 프로세스 내 스레드다.** 서버를 재시작하면 진행 중이던 실행은 다시 돌려야 한다.
- **운영 전**: 비밀 키 설정, HTTPS와 원내망 제한, LibreOffice 설치, 운영 DB 전환과 백업, AI 사용 시 기관 승인.
