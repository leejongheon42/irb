# 기능 및 화면 안내

IRB 자동화 솔루션 v3.0의 **구현된 기능**과 **화면별 내용**을 한 문서로 정리했습니다. 세부 설명은 각 절의 링크 문서를 참고하십시오.

- 데모 계정 아이디: `researcher`(연구자) · `coordinator`(IRB 간사) · `chair`(위원장) · `reviewer1~4`(심의위원) · `steward`(데이터관리자) · `admin`(시스템관리자)
- 자동 분류·검토 결과는 **권고**입니다. 최종 판단은 IRB가 합니다.

---

## 1. 전체 업무 흐름

```
사전 대상자 수 조회 → 과제 작성(또는 타 기관 계획서 가져오기) → 서류 업로드·자동 작성
→ 자동 사전점검 → 전자서명 제출 → 사무국 접수·보완 요청 → 위원 배정·심의(또는 위원회 회의)
→ 결정·통지서(승인 도장본) → 가명처리·적정성 검토 → 자료 제공(계약 확인) → 결과 반출 심사
→ 변경·지속·종료 신청 → 자료 파기 확인
                ▲ 서류가 저장될 때마다 AI 문서 분석 파이프라인이 자동 실행됩니다
```

## 2. 역할과 메뉴

| 역할 | 보이는 주요 메뉴 |
|---|---|
| 연구자 | 연구과제, 새 과제 작성, 계획서 가져오기, 대상자 수 사전 조회, 관련 정보 검색, 근거 질의응답, 서식 자료실, 알림, 결과 반출 심사, 자료 파기 관리 |
| IRB 간사 | 위 메뉴 + 접수 대기, 심의중, 위원회 회의, 가명처리 적정성 검토, 서류 검토 대기열, 성과지표, 연간 운영실적, 감사 로그, 사전검토 규칙, 기관 프로필·양식·서식, 지식 관리, AI·문서 자동화, 자료 제공 계약, 처리기록 대장 |
| 위원장·심의위원 | 배정된 심의, 위원회 회의, 가명처리 적정성 검토, 서류 검토 대기열, 관련 정보 검색 |
| 데이터관리자 | 가명처리 작업, 가명처리 시작, 자료 제공 계약, 처리기록 대장, 결과 반출 심사, 자료 파기 관리 |
| 시스템관리자 | 전체 메뉴 + 사용자 관리 |

## 3. 화면별 내용

### 3-1. 공통

| 화면 (주소) | 내용 |
|---|---|
| 로그인 `/login` | 아이디·비밀번호 로그인. 5회 실패 시 10분 잠금. 세션은 8시간 유지. |
| 대시보드 `/` | 역할별 현황. 간사: 상태별 건수, 접수·심의 대기열, 만료 임박 승인, 기한 초과 심의. 연구자: 내 과제와 필요한 조치. 위원: 나의 심의 배정. |
| 검색 `/search` | 과제·계약 통합 검색(상단 검색창). |
| 알림 `/notifications` | 시스템 알림 목록, 읽음 처리, 관련 화면으로 이동. 메일(SMTP) 발송은 선택. |

### 3-2. 연구과제

| 화면 | 내용 |
|---|---|
| 과제 목록 `/protocols` | 상태·유형별 목록과 필터. 접수 대기·심의중 바로가기. |
| 과제 작성·수정 `/protocols/new`, `/{id}/edit` | 기본정보 · 연구내용 · 데이터 · 개인정보 보호 · 동의 · 이해상충 섹션 + **기관 추가 항목**. 저장 즉시 자동 사전점검. |
| 계획서 가져오기 `/protocols/import` | 타 기관 양식의 계획서(PDF·DOCX·HWPX·HWP 등)를 올리면 항목을 추출해 새 과제 초안 생성. |
| 과제 상세 `/protocols/{id}` | 탭 구성: **개요**(요약·기관 추가 항목·웹 작성 서식 카드) / **사전검토**(권고 유형·위험도·동의 면제·필요 서류·검토 의견별 관련 근거·유사 과제·전자서명 제출) / **서류**(제출 현황판·업로드·자동 작성) / **심의**(위원 배정·의견·결정) / **의견**(사무국·연구자 코멘트) / **데이터**(가명처리·계약·반출·파기 현황) / **이력**(감사 이력). 상단 버튼: 사전검토 보고서 출력, AI 문서 분석, 웹 작성 서식. |
| 사전점검 `/protocols/{id}/precheck` | 제출 전 저장 내용 기준 자동 점검. 필수 보완이 남으면 제출 불가. |
| 변경 대비표 `/submissions/{id}/diff` | 재제출·변경 시 이전 제출본과 항목별 차이. |
| 지속·종료 보고 `/protocols/{id}/report/{kind}` | 경과보고·종료보고 작성(종료보고 확인 시 파기 기한 자동 설정). |
| 통지서 `/decisions/{id}/letter` | 결정 통지서 인쇄본(기관 문구는 기관 프로필 반영). |

## 4. 자동 사전검토 엔진

- **심의유형 분류:** 면제 / 신속 / 정규. 근거와 법적 조항을 함께 표시합니다.
- **위험도 점수:** 요인별 가중치 합산, 최소위험 기준 판정. 점수 근거 표시.
- **동의 면제 판정:** 생명윤리법 제16조제3항 요건(동의 취득 곤란·타당성 영향·최소위험) 검증.
- **필요 서류·체크리스트:** 조건별(`consent_waiver`, `external_transfer`, `ai_ml` 등) 자동 산정.
- **검토 의견:** 30여 개 규칙(법적 근거·조치 방법 포함), 공동연구자 교육 만료, 다기관·위임심의, 기관 추가 항목 규칙.
- 규칙은 `irb_automation/rules/default_ruleset.yaml` 한 파일로 관리하며 서버 재시작 없이 반영됩니다.

## 5. 보안 · 감사

역할 기반 권한, CSRF 토큰, CSP(`default-src 'self'`, 외부 CDN 없음), 클릭재킹 방지, 로그인 잠금, PBKDF2 비밀번호 해시, 해시 체인 감사 로그, 전자서명(내용 해시), 업로드 시그니처 검증, 가명화 키(HMAC)와 매핑표 분리 보관, AI 전송 전 개인정보 마스킹.

## 7. 구현 범위와 한계

**구현됨:** 위 3~6절 전체. 테스트 170여 개(사전검토, 가명처리, 업무 흐름, 위원회, 전자서명, 거버넌스, 기관 양식, 서식 엔진, 웹 제출, AI 파이프라인, 지식 검색, 통합)가 통과합니다.

**알려진 한계**
- 실제 Claude API 호출은 키가 없어 가짜 클라이언트로만 검증했습니다(AI 기본 꺼짐, 꺼져도 규칙 기반으로 동작).
- 로컬 OCR이 없어 AI 없이는 스캔 PDF·이미지를 읽지 못합니다.
- 구형 HWP·DOC 서식은 HWPX/DOCX로 다시 저장해야 하며, HWPX는 실제 한컴 파일로 검증하지 못했습니다.
- 자체 계정 인증입니다(병원 SSO는 `web/deps.py` 교체로 연동). SQLite는 단일 서버용입니다.
- 검색은 단어 기반이라 동의어를 놓칠 수 있고, 법령 요약은 개정을 자동 반영하지 않습니다.
- 서버 재시작 시 진행 중이던 분석은 "진행 중"으로 남아 재분석이 필요합니다.
- 기본 규칙은 참고용이므로 **각 기관 SOP에 맞게 검토·수정**한 뒤 사용해야 합니다.
