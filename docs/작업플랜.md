# OpenRouter 무료 모델 연동 작업 플랜

작성일: 2026-11-15
관련 문서: [LLM 연동 현황 및 무료 모델 매칭](LLM_연동_현황_및_무료모델_매칭.md)

호출부 9곳은 거의 건드리지 않고, `irb_automation/ai/client.py` 안에 OpenRouter 경로를 추가해 Anthropic 형태의 응답으로 돌려주는 방식을 권장한다. 호출부가 `create_message` / `structured_call` / `text_call`만 쓰고 있어서 예외는 OCR과 지식 질의응답 인용 두 곳뿐이다.

OpenRouter 쪽 사양(한도, PDF 처리, 모델 목록)은 작성 시점에 다시 조회하지 않았고 기억 기준이므로 0단계에서 확인한다.

---

## 0단계 — 사전 확인 (코드 변경 없음)

- OpenRouter 키를 발급하고, 개인정보 설정에서 무료 엔드포인트의 학습·로깅 허용을 켠다. 꺼져 있으면 무료 모델이 404로 거절되는 것으로 기억한다.
- 무료 한도를 확인한다. 크레딧 미충전 시 일 50회 안팎, 소액 충전 시 일 1,000회 수준으로 기억한다.
- 매칭 문서의 모델 ID가 아직 살아 있는지 `/api/v1/models`로 다시 조회한다.

## 1단계 — 공급자 어댑터 (핵심)

대상: `irb_automation/ai/client.py`, `irb_automation/config.py`, `.env.example`, `requirements-ai.txt`

- 설정 추가: `IRB_AI_PROVIDER=anthropic|openrouter`(기본 `anthropic`), `OPENROUTER_API_KEY`.
- `create_message`를 공급자별로 분기한다. 기존 Anthropic 경로는 그대로 둔다.
- OpenRouter 경로는 `httpx`로 `/api/v1/chat/completions`를 직접 호출한다. `openai` SDK보다 의존성이 가볍다.
- 요청 변환:
  - `system`은 system 메시지로 보낸다.
  - `image` 블록은 `image_url`(data URL)로 바꾼다.
  - 텍스트 `document` 블록은 `[문서 n] 제목` 머리말이 붙은 텍스트로 바꾼다.
  - `output_schema`는 `response_format: json_schema`로 보낸다.
  - `effort`, `betas`, `fallbacks`는 버린다.
- 응답 변환: `content[].text`, `stop_reason`, `usage.input_tokens/output_tokens`, `model`을 가진 객체로 감싼다. `finish_reason`의 `length`는 `max_tokens`로, `content_filter`는 `refusal`로 대응시킨다.
- 오류 정규화:
  - 401은 `AIUnavailable`, 402·404·429는 `AIError`로 변환한다.
  - 200 응답 본문에 `error`가 들어오는 경우도 처리한다.
  - 429는 `Retry-After`를 따라 1~2회만 재시도한다.
- `ai_enabled()`는 openrouter일 때 anthropic SDK 대신 키 존재 여부로 판정한다.
- "Claude API …" 오류 문구를 공급자 중립으로 바꾼다.

## 2단계 — 기능별 모델 매핑

- `purpose` 값이 지금은 한글 라벨과 `knowledge_answer`가 섞여 있다. 화면 표시용 라벨은 유지하고, 매핑용 안정 키(`prereview`, `qc`, `draft`, `revision`, `ocr`, `classify`, `extract`, `summary`, `knowledge`)를 client 안에서 대응시킨다.
- `irb_automation/ai/openrouter_models.yaml`을 새로 만들어 기능별 1순위, 대안, 출력 토큰 상한을 둔다. 내용은 매칭 문서 6장 표를 그대로 옮긴다.
- 대안 모델은 OpenRouter의 `models` 배열(서버측 폴백)로 넘기고, 마지막에 `openrouter/free`를 둔다.
- QC와 OCR이 `max_tokens=32000`을 요청하므로 모델별 상한으로 잘라낸다.

## 3단계 — 구조화 출력 안정화

- 스키마를 쓰는 5개 기능(#1, 2, 6, 7, 8)의 스키마가 strict 모드 조건을 만족하는지 점검한다. 조건은 `additionalProperties: false`와 전 필드 `required`이다.
- JSON 파싱에 실패하면 "스키마를 프롬프트에 넣고 `json_object`로 1회 재시도"하는 폴백을 `structured_call_with_response`에 추가한다. 코드펜스 제거도 포함한다.

## 4단계 — OCR (#5)

대상: `irb_automation/docproc/text.py` (176행 부근)

- 스캔 PDF는 `pdf_block` 대신 쪽별 PNG로 렌더링해 `image_block` 여러 개로 보낸다.
- 렌더링에는 `pypdfium2`를 권장한다. PyMuPDF는 AGPL이라 피한다.
- 3~5쪽씩 묶어 호출하고 결과를 이어 붙인다. 20쪽 문서면 4~7회 호출이라 무료 한도를 가장 많이 쓴다.
- 쪽수 상한 설정(`IRB_AI_OCR_MAX_PAGES`)을 둔다.
- Anthropic 경로는 기존 `document` 블록을 유지한다.

## 5단계 — 지식 질의응답 인용 (#9)

대상: `irb_automation/knowledge/service.py` (300행 부근 `_ai_answer`)

- OpenRouter일 때는 문서에 번호를 붙여 보내고, 프롬프트로 문장 끝에 `[n]` 표기를 요구한다.
- 응답에서 `[n]`을 정규식으로 뽑아 기존 `citations` 구조로 조립한다. `cited_text`는 원문 인용 대신 검색 발췌(snippet)로 채운다.
- 번호가 하나도 없으면 기존 추출형 답변으로 넘어간다.

## 6단계 — 화면·문서·검증

- AI 상태 화면(`irb_automation/web/routes_pipeline.py` 275행 부근)에 공급자와 기능별 모델을 표시한다.
- 같은 화면에 무료 공급자 사용 시 "더미 데이터 전용" 경고를 띄운다.
- 단위 테스트는 `httpx.MockTransport`로 블록 변환, 스키마, 종료 사유, 오류, 모델 매핑을 검증한다. 기존 `tests/test_pipeline.py`와 `tests/test_knowledge.py`는 수정 없이 통과해야 한다.
- 실호출 스모크 스크립트로 더미 문서에 대해 9개 기능을 한 번씩 돌려 한국어 품질과 JSON 준수를 확인하고, 결과에 따라 매핑을 조정한다.
- `.env.example`과 매칭 문서를 갱신한다.

## 위험 요소

- **한도**: 파이프라인 1회에 분류·추출·요약·QC가 연달아 호출되므로, 크레딧 미충전 상태면 시연 몇 번에 일일 한도가 소진될 수 있다.
- **개인정보**: 무료 모델은 입력이 로깅·학습될 수 있어 실제 연구 문서에는 쓰면 안 된다. 기존 `mask_text` 마스킹은 유지되지만 그것만으로는 충분하지 않다.
- **품질**: 한국어 의료·IRB 문서에 대한 무료 모델 품질은 미검증이다. 6단계 스모크 결과가 좋지 않으면 OCR과 사전검토만 Claude Haiku로 돌리는 혼합 구성이 대안이다.
