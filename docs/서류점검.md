# 서류 품질 점검과 자동 교정

IRB에 제출하기 전에 서류를 같은 기준으로 점검하고, 고칠 수 있는 부분은 원본 서식을 유지한 채 고쳐 돌려줍니다.
교차 문서 불일치·버전 오류·필수 기재사항 누락은 IRB 보완 요청의 가장 흔한 원인입니다.

## 1. 사용 방법

| 방법 | 화면 | 특징 |
|---|---|---|
| 과제 서류 점검 | 과제 › 제출 서류 패키지 › 서류 점검 (또는 자동 완성 실행 시 자동) | 서류함의 현행본 전체 + **과제 입력값과 대조**, 교정본을 새 버전으로 저장 |
| 빠른 점검 | 서류 품질 점검 (`/qc`) | 과제 없이 파일만 올려 점검. 과제를 선택하면 과제 정보와도 대조 |
| 샘플 체험 | `/qc` › 샘플 서류로 체험 | 의도적으로 문제를 넣은 계획서 v3.0 + 동의서 |

결과 화면에는 다음이 나옵니다.
- 점수와 PASS/FAIL
- Critical·Major·Minor 건수
- 3단계 스캔 상태
- 서류별 이슈: 근거 문장과 권고, 자동 교정 문구(삭제 → 교정)

## 2. 3단계 스캔

| 단계 | 방식 | 점검 |
|---|---|---|
| Phase 1 규칙 기반 | 결정론적(같은 입력 → 같은 결과) | 필수 기재사항, 버전, 미기입·자리표시자, 실제 개인정보, 규제(보관 기간·동의 계획), 용어 통일, 교차 문서·과제 정보 대조 |
| Phase 2 AI 심층(선택) | Claude, 개인정보 마스킹 후 전송, 이미 찾은 이슈는 중복 지적하지 않음 | 문맥 모순, 위험 설명 축소, 규제 비준수, 가독성, 의학 용어·용량 오기 |
| Phase 3 오탈자·숫자 | 결정론적 | 오탈자 사전, 단어 반복, 존재하지 않는 날짜, 기간 역전, 한 문서 안의 서로 다른 용량·방문·기간 표기 |

AI가 제안한 교정은 교정할 원문이 문서에 그대로 있을 때만 자동 교정 대상이 됩니다. AI가 꺼져 있으면 Phase 1·3만 실행합니다.

## 3. 판정

- 감점: Critical −15, Major −7, Minor −2 (100점 시작)
- **Critical이 1건이라도 있으면 점수와 무관하게 FAIL**
- 80점 미만이면 FAIL
- 값은 `criteria.yaml`의 `scoring`에서 바꿉니다.

## 4. 교차 대조 항목

추출한 값을 서류끼리, 그리고 **과제 정보(입력값)** 와 비교합니다. 과제 정보에 값이 있으면 그것이 기준값이고, 없으면 연구계획서(없으면 다수결)가 기준입니다.

| 항목 | 중요도 | 인식 예 |
|---|---|---|
| 연구대상자 수 | Critical | "목표 연구대상자 수는 총 1,200명", "총 120명의 대상자" |
| 투여 용량·횟수 | Critical | "1일 1회 100mg", "하루 2회 200㎎" |
| 방문 횟수 | Critical | "총 8회 방문", "방문 횟수: 6회" |
| 참여(시험) 기간 | Critical | "시험 기간은 총 12주" |
| 연구 기간 | Critical | "연구 기간: 2026.12.01 ~ 2027.11.30" |
| 시험약 명칭, 자료 수집 기간, 보관 기간, 연구책임자, 연구 제목 | Major | |

교정 문구는 원문 형식을 유지합니다. 예를 들어 `2026년 1월 5일 ~ …`은 `년·월·일` 형식 그대로, `1,500명`은 천 단위 구분 기호를 유지해서 고칩니다.

## 5. 자동 교정

- **DOCX**: 두 가지 파일을 만듭니다. 표·머리글·바닥글·각주와 글자 서식은 그대로 둡니다.
  - **변경 추적본**: `w:del`·`w:ins`로 바꾼 곳을 표시합니다. Word나 한컴오피스에서 변경 내용을 확인한 뒤 수락할 수 있습니다.
  - **수정 완료본**: 고친 곳에 노란 형광펜을 칩니다.
  - **글꼴 통일**(선택): 모든 글자의 한글·영문 글꼴을 지정한 글꼴로 맞춥니다.
- **HWPX**: 문단(`hp:p`) 안에서 텍스트만 바꿉니다. 변경 추적은 지원하지 않습니다.
- **PDF·HWP(구형)**: 자동 교정할 수 없으므로 원본(DOCX·HWPX)을 올려야 합니다.
- **자동으로 쓰지 않는 것**: 필수 기재사항 누락처럼 내용을 새로 써야 하는 항목은 연구자가 직접 작성해야 합니다.
- **과제 서류에 적용한 경우**: 수정 완료본이 새 버전으로 저장됩니다. '다시 점검'으로 확인하십시오.

## 6. 점검 기준 수정 (`irb_automation/qc/criteria.yaml`)

기관용 사본을 만들어 `IRB_QC_CRITERIA_PATH`로 지정합니다. 파일을 저장하면 다음 점검부터 반영됩니다.

| 키 | 내용 |
|---|---|
| `required.<서류 종류>` | 필수 기재사항: `any`(하나라도) / `all`(모두) 키워드, `re:` 정규식, `when`(children·waiver·obtain·identifiable·prospective·ai_ml·external_transfer 조건) |
| `terminology` | 표준 용어와 변형 목록 |
| `typos` | 틀린 표현 → 바른 표현 |
| `placeholders` | 미기입 표지 |
| `cross_fields` | 교차 대조 항목별 중요도 |
| `regulatory.min_retention_years` | 최소 보관 기간 |
| `scoring` | 감점·통과 점수·Critical FAIL 여부 |

## 7. 한계

- 값 추출은 한국어 IRB 서류의 일반적인 표현 패턴을 기준으로 합니다. 표현이 특이하면 놓칠 수 있고, AI 단계를 켜면 보완됩니다.
- 스캔본(이미지 PDF)은 텍스트가 없어 점검할 수 없습니다(AI 문서 인식 OCR 필요).
- 필수 기재사항은 키워드 존재 여부로 판정하므로, 내용이 충분한지는 연구자가 확인해야 합니다.
