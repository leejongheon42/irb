> v4.0: IRB 사무국의 문서별 검토·승인 도장 기능은 제거되었습니다. 서류함은 연구팀의 작업 공간이며, 제출 전 점검은 [서류점검.md](서류점검.md)를 참고하십시오.

# 웹 기반 문서 제출

연구자는 브라우저에서 서류를 제출하고, IRB 사무국과 배정된 심의위원은 서류를 하나씩 미리 보고 확인하거나 보완을 요청합니다. 승인되면 시스템이 승인 도장본을 자동으로 만들어 줍니다. 모든 행위는 감사 로그에 남습니다.

## 1. 서류 올리기 (과제 상세 → 서류함)

- **다중 업로드**: 파일을 끌어다 놓거나 여러 개를 한 번에 선택합니다(기본 최대 20개). JavaScript를 쓸 수 없는 환경에서도 다중 선택 업로드가 동작합니다. 이때 종류는 '자동 추정' 또는 일괄 선택으로 정해집니다.
- **서류 종류 추정**: 파일명 키워드(동의서·설명문, 이력서·CV, 이수증·CITI, 이해상충·COI, 계획서·Protocol, CRF·증례기록, 가명처리, 보안서약, 계약서 등)로 파일마다 기본값을 채웁니다. 파일명으로 판단할 수 없으면 서버에서 문서 내용을 분석합니다. 이 분석에는 문서 인식 모듈(`docproc.classify`)이 필요합니다.
- **결과 요약**: 성공·경고·거부 건수와 파일별 사유를 보여 줍니다.

### 자동 검증 (`submission/validate.py`)

| 검사 | 처리 |
|---|---|
| 확장자 화이트리스트(PDF, HWP/HWPX, DOC/DOCX, XLS/XLSX, CSV/TXT, JPG/PNG, ZIP) | 목록 밖이면 거부 |
| 매직바이트 판별(PDF, OOXML·HWPX 필수 엔트리, HWP5/OLE, PNG/JPEG) | 확장자와 실제 형식이 다르면 거부(위장 파일 차단) |
| 실행 파일·HTML/스크립트 | 거부 |
| 빈 파일, 크기 제한(`IRB_MAX_UPLOAD_MB`) | 거부 |
| PDF 손상·쪽 없음 | 거부 |
| 비밀번호 PDF / 암호 설정 HWP | 거부(`submission.reject_encrypted_pdf`) |
| PDF 스크립트·실행 동작·내장 파일 | 경고 |
| 매크로 포함 OOXML(.docm 위장) / 압축 폭탄 | 거부 |
| 같은 과제에 동일 파일(SHA-256) 존재 | 경고 |

검증 결과(형식·쪽수·경고)는 `Document.validation`에 저장되며 현황판과 미리보기에 표시됩니다. 거부된 파일은 저장하지 않고 감사 로그(`document_reject`)에만 기록합니다. 저장할 때는 파일명을 정리합니다(경로를 제거하고 특수문자는 `_`로 바꿈).

### 버전 관리

같은 종류의 서류를 다시 제출하면 새 버전이 현행본이 되고, 이전 파일은 `이전 버전(superseded)` 상태로 보존됩니다. 업로드·자동 작성·자동 변환·승인 도장본에 모두 같은 규칙이 적용됩니다(`submission.versions.register_new_version`).

심의 중(접수·심의중)에는 **보완 요청된 서류와 아직 제출하지 않은 서류만** 연구자가 제출할 수 있습니다. 심의 중인 서류를 무단으로 바꾸지 못하게 하기 위해서입니다. 승인·면제 이후에는 `submission.report_doc_types`(경과·종료보고서, 파기확인서 등)만 제출할 수 있고, 나머지는 변경 신청 뒤에 제출합니다. 사무국은 상태와 관계없이 제출할 수 있습니다.

## 2. 버전 비교

`/documents/{id}/compare?with={다른버전id}`는 텍스트를 줄 단위로 비교합니다(추가·삭제·유사도). PDF, TXT/CSV, 자동 작성 HTML은 기본으로 비교할 수 있고, HWP/DOCX는 문서 인식 모듈(`docproc.text.extract_text`)이 있을 때 비교할 수 있습니다.

## 3. 합본(PDF)·e-IRB 업로드용 ZIP

- **ZIP** `/protocols/{id}/bundle.zip`: 현행본 전체, 표지(HTML), `manifest.json`이 들어 있습니다. manifest에는 파일명·종류·버전·상태·SHA-256·업로드자·시각·무결성 대조 결과가 기록됩니다.
- **PDF 합본** `/protocols/{id}/bundle.pdf`: 표지와 목차(쪽 번호) 뒤에 PDF와 PDF로 변환된 문서를 병합하고, 문서마다 책갈피를 답니다. 병합할 수 없는 문서는 목차에 '별도 첨부'로 표시합니다.
- 연구팀, 사무국, 배정 위원만 내려받을 수 있으며 감사 로그(`document_bundle`)에 기록됩니다.

## 4. 설정 (`rules/default_ruleset.yaml` → `submission:`)

```yaml
submission:
  max_files_per_upload: 20
  reject_encrypted_pdf: true
  warn_pdf_active_content: true
  stamp_doc_types: [consent_form, protocol]
  stamp_all_pages: true
  report_doc_types: [progress_report, final_report, destruction_certificate, other]
```

## 5. 연동 지점

- `submission.hooks.after_document_saved(db, user, document)`: 업로드 직후 호출됩니다. `pipeline.service.start_document_pipeline`이 있으면 실행하고, 실패해도 업로드는 유지됩니다.
- `submission.service.store_document(...)`: 검증 → 저장 → 버전 등록 → 감사 → hook 순서로 처리하는 공용 진입점입니다.
- `submission.seed.seed_submission(db)`: 데모 문서에 합성 PDF를 만들고 승인 과제의 도장본을 생성합니다(멱등).
