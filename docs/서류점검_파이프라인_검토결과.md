# 서류 점검 파이프라인 구현 검토 결과

검토일: 2026-11-14 · 대상: 작업 트리(미커밋) `irb_automation/qc` 외
기준: [작업 계획](서류점검_파이프라인_작업계획.md) · [작업 결과](서류점검_파이프라인_작업결과.md)

이 문서는 LLM 코딩 에이전트가 그대로 수정 작업에 쓸 수 있게 **위치 · 재현 · 수정 방향 · 완료 기준**으로 적었다. 항목 번호(F-xx)는 권장 수정 순서다.

## 1. 요약

- 작업 결과 문서의 검증 수치는 재현된다: `pytest` 203건 통과, `ruff` 통과, `qc-eval` 46건(검출 45/45, 오탐 0, 재현성 100%).
- 뼈대(프로필 → 묶음 검사 → 범위 비교 → 후보/확정 → 점수 5상태 → 보고서)는 계획대로 들어갔다. 기준값 추정 금지, 80점 커트라인 제거, AI 후보 비감점도 반영되어 있다.
- 그러나 **실제 서류에서는 PASS에 도달할 수 없고, 대표적인 불일치를 조용히 놓치거나 정상 문서를 Critical로 지적하는 경우**가 있다. 아래 11건은 합성 문장으로 직접 실행해 확인했다(재현 스크립트의 입력을 항목마다 적었다).
- 검토 방법: 변경된 QC 모듈 전부와 라우트·기준 YAML을 읽고, 의심 지점을 `run_rules` + `annotate` + `group_issues` + `assess`로 직접 실행했다. **화면(브라우저)과 실제 DOCX/HWPX, AI 호출은 실행해 보지 않았다.** 템플릿은 일부만 읽었다.

| 구분 | 건수 | 내용 |
|---|---|---|
| A. 판정 흐름이 막힘 | 3 | 확인 필요가 확정으로 못 감, 필수 항목 전부 비감점, 묶음 검사로 상시 HOLD |
| B. 놓침(미탐) | 4 | 기간 종류 분리, 용량 필드 분리, mg/kg, 프로필 오판으로 규칙 생략 |

| D. 개선 | 9 | 완료율, 프로필 입력, 재점검, AI 중복, 미구현 플래그 등 |
| E. 문서 정정 | 3 | `서류점검.md`, 작업 결과 문서 |

## 2. A. 판정 흐름이 막히는 문제 (최우선)

### F-01 `확인 필요` 이슈를 오류로 확정할 방법이 없다

- 위치: `qc/review.py:25-35`(`transition`), `web/templates/qc/run.html:141-143`
- 현상: `result == "needs_check"`인 이슈에 허용되는 조치는 **오탐 철회(사유 필수)뿐**이다. `confirmed`는 `"판독·적용 범위 또는 근거가 확인되어야 확정할 수 있습니다"`로 거절된다. "확인했더니 실제 오류였다"로 가는 전이가 없다.
- 영향을 받는 이슈: 약물명 불일치(`CROSS_DRUG`, 항상 `alias_unknown`), 제목·기관 불일치, 범위 불명확한 모든 교차 불일치, `basis` 없는 필수 항목 전부, `의미가 다른 용어 혼동`, `사실값 변경 가능 오기`, 인용 미확인 AI 지적, 규정 지적.
- 재현: 계획서 `시험약: ABC정`, 동의서 `시험약: XYZ정` → `CROSS_DRUG critical needs_check alias_unknown` → 확정 시도 시 `ReviewError`. **Critical인 약물 정체성 불일치를 감점할 수 없다.**
- 수정 방향:
  1. 전이 추가: `candidate(needs_check) → candidate(mismatch|missing)` — 조치명 `resolve_check`, 입력은 **확인 결과(사유 필수)** 와 사유 코드별 답변.
     - `scope_unclear`: "같은 범위다" → `result="mismatch"` / "다른 범위다" → `dismissed`
     - `alias_unknown`: "다른 대상이다" → `mismatch` / "같은 대상의 다른 이름이다" → `dismissed`
     - `basis_unverified`: "적용된다(근거 입력)" → `missing`·`mismatch` + `basis` 저장 / "적용되지 않는다" → `na`
     - `applicability_unknown`: 프로필 값을 고치게 하고 재실행(F-13)
  2. 확인 결과를 `issue["check_answer"] = {"by", "at", "answer", "note"}`로 남기고 감사 로그에 기록.
  3. 템플릿에 사유 코드별 선택지 버튼.
- 완료 기준: 위 재현에서 "다른 대상이다" 선택 → 확정 → `FAIL`, 85점. `needs_check` → 확정 직행은 계속 거절.

### F-02 필수 기재사항(M06)이 사실상 전부 비감점이고 PASS에 도달할 수 없다

- 위치: `qc/units.py:25-27`, `criteria.yaml`(모든 `required` 항목의 `basis`가 비어 있음), `required_unverified: needs_check`
- 현상: `basis`가 없는 `REQ_*`는 전부 `needs_check: basis_unverified`가 된다. 현재 `basis`가 채워진 항목이 0개이므로 **철회 권리를 뺀 필수 항목 누락은 어떤 경우에도 감점되지 않는다.** 동시에 이 이슈들은 F-01 때문에 철회만 가능해서, 짧은 문서 2개만 올려도 확인 필요 36건·완료율 12%·상시 `HOLD`가 된다(재현: 3줄짜리 계획서 + 3줄짜리 동의서 → 이슈 38건 중 37건이 확인 필요).
- 이것은 계획 7장 D3의 기본값을 그대로 구현한 결과다. 구현 잘못이 아니라 **기본값이 운영에 맞지 않는다.**
- 수정 방향(택1, 권장은 ①+③):
  1. `required_unverified: candidate`로 기본값 변경. `basis`가 없으면 이슈에 "근거 미검수" 배지를 달고 **후보**로 낸다(확정은 검토자). 확신도와 등급을 분리하라는 원칙(R6)에도 맞다.
  2. 기본값을 유지하되 F-01의 `resolve_check`로 풀 수 있게 한다.
  3. 같은 문서의 `basis_unverified` 이슈를 **문서당 1장의 묶음 카드**로 보여 주고 "모두 후보로 전환 / 모두 해당 없음"을 한 번에 처리.
  4. 근본 해결: 공용 IRB 권고 서식(제38·39·40·43·44·45호) 원문을 받아 항목별 `basis`를 채운다(계획 T-1A와 같은 선행 조건).
- 완료 기준: 위험·이익·개인정보 절이 없는 동의서가 Critical/Major **후보**로 나오고 예상 점수에 반영된다.

### F-03 묶음 검사(E10)가 일부 문서만 점검하려는 사용을 막는다

- 위치: `qc/bundle.py:45-56, 66-94`, `routes_package.py`의 `bundle-answer`
- 현상:
  - 과제를 선택하면 `committee="institution"`이 되어 기관 체크리스트 전 항목(이력서·교육이수증·이해상충·예산서 등)이 `level: required`로 들어온다. 계획서와 동의서 2개만 대조하려 해도 나머지가 전부 "제출 여부 확인" 이슈가 된다.
  - 답변은 `해당 없음`과 `e-IRB 입력`(일부 문서만)뿐이다. **"이번 점검 범위 아님 / 나중에 제출"** 이 없다.
  - `applicability_unknown` 사유의 묶음 이슈는 `bundle-answer`를 쓸 수 없고(`reason == "file_missing"`만 허용) 철회만 가능하다.
- 수정 방향:
  1. 답변에 `later`(추후 제출: 단위는 `needs_check` 유지하되 이슈는 접어서 표시)와 `out_of_scope`(이번 점검 범위 아님: `na`) 추가.
  2. 업로드 화면에 "이 파일들만 서로 대조(묶음 구성 검사 안 함)" 선택지. 켜면 `inspect_bundle`을 건너뛰고 E10 단위를 만들지 않는다. `run_for_protocol(doc_ids=...)`로 일부만 고른 경우도 같은 처리.
  3. `applicability_unknown` 묶음 이슈는 프로필 문항으로 연결(F-13).
  4. 계획 T-05의 "다른 연구 문서 혼입 가능"(E01 값 전부 불일치 → Major 후보)은 미구현이다. 추가.
- 완료 기준: 계획서+동의서만 올리고 "서로 대조만"을 켜면 E10 이슈 0건.

## 3. B. 놓치는 불일치 (미탐)

비교 키가 `(key, field, scope)`로 세분화되면서 **서로 다른 필드로 분류된 값은 아예 비교되지 않고, 확인 필요도 남지 않는다.** 계획 R1("애매하면 확인 필요")과 어긋난다.

### F-04 기간: `시험 기간`과 `참여 기간`이 비교되지 않는다

- 위치: `qc/facts.py:200-204`(`_with_scope`의 duration 분기), `qc/compare.py:33`
- 재현: 계획서 `시험 기간은 총 12주이다.` / 동의서 `참여 기간은 총 24주입니다.` → 이슈 0건. 이 조합은 MIRA 공개 예시(Protocol–ICF 시험 기간)이자 기존 샘플의 핵심 사례다.
- 원인: 라벨 접두어로 `period_trial` / `period_individual` / `period_treatment` / `dose_duration` / `period_followup`으로 나뉘고, 필드가 다르면 그룹이 달라 문서 2개 조건을 못 채운다.
- 수정 방향: 필드 **호환 그룹**을 둔다. `{period_trial, period_individual, period_treatment}`는 같은 그룹으로 묶어 비교하되, 필드명이 서로 다르면 불일치가 아니라 `needs_check: scope_unclear`("시험 기간과 참여 기간이 같은 기간을 뜻합니까?")로 낸다. `rules.yaml`에 `compatible_fields`로 정의.
- 완료 기준: 위 재현 → M05 확인 필요 1건. `참여 기간 12주` vs `참여 기간 24주` → 불일치 후보(현행 유지). 전체 연구 2년 vs 개인 12주 → 이슈 없음(현행 유지).

### F-05 용량: `dose_unit`과 `dose_daily`가 비교되지 않는다

- 위치: `qc/facts.py:207-213`
- 재현: 계획서 `시험약은 1일 1회 50mg 투여한다.` / 동의서 `시험약을 매일 아침 100mg 복용합니다.` → 이슈 0건.
- 원인: `1일|하루|매일`로 시작하고 `N회`가 없으면 `dose_daily`, 있으면 `dose_unit`. 두 문서가 다른 필드가 된다.
- 수정 방향: F-04와 같은 호환 그룹(`dose_unit`↔`dose_daily`). 한쪽에 빈도가 명시되어 환산 가능하면(`1일 1회 50mg` = 1일 50mg) 환산 후 비교하고, 환산 근거가 없으면 `needs_check`.
- 완료 기준: 위 재현 → M03 후보 또는 확인 필요 1건.

### F-06 `mg/kg`를 `mg`로 읽어 일치로 처리한다

- 위치: `qc/facts.py:109-112`(`_DOSAGE`), `:213`
- 재현: 계획서 `1회 5mg/kg` / 동의서 `1회 5mg` → 이슈 0건(둘 다 `5mg`로 정규화되어 **일치**로 기록).
- 원인: `_DOSAGE`가 단위 뒤 `/kg`을 버린다. 불확실 표시용 정규식 `\b(?:mg|g)\s*/\s*kg`은 `5mg`처럼 숫자에 붙은 경우 `\b`가 성립하지 않아 걸리지 않는다. `numeric_checks.py:31`의 `mg\s*/`와도 판단이 다르다.
- 수정 방향: `_DOSAGE`의 단위 그룹에 `(?:/\s*(?:kg|m2|㎡|day|일))?`를 포함해 **분모까지 단위로 보존**(`5mg/kg`). 단위가 다르면 같은 그룹에 넣되 `needs_check`(계획 9장 M03 예외). `\b` 제거.
- 완료 기준: 위 재현 → 확인 필요 1건, `5mg/kg` vs `5mg/kg` → 일치.

### F-07 프로필 자동 추정이 틀리면 규칙이 조용히 생략된다

- 위치: `qc/profile.py:47-65`, `qc/checks.py:268-270`, `qc/service.py:119-122`
- 재현과 문제:
  | 입력(계획서 본문) | 추정 결과 | 문제 |
  |---|---|---|
  | `시험약 투여 용량은 표 3 참조. 의무기록을 검토한다.` + 동의서에 `1회 100mg` | `drug=False` | 용량 정규식이 계획서에서 못 뽑고 `의무기록`이 있다는 이유로 "약물 없음" 확정 → M02·M03이 `해당 없음`으로 빠진다 |
  | `제외 기준: 만 19세 미만 아동은 제외한다.` | `vulnerable=["children"]` | **제외** 문구인데 소아 연구로 판단 → 법정대리인·아동 승낙 항목이 요구된다 |
  | `혈액 검체를 채취한다.`(약물 임상시험에 흔함) | `study_type="specimen"` | `human`·`both`는 추정 경로가 없다. 인체유래물 동의서가 필수로 뜬다 |
  - 또 `drug`·`vulnerable`·`study_type` 추정은 **`doc_type == "protocol"`인 문서 본문만** 본다. 동의서만 올리면 아무것도 추정되지 않는다.
- 수정 방향:
  1. `drug=False`를 문서에서 확정하지 않는다. 어느 문서에서든 용량·시험약 표현이 하나라도 있으면 `True`, 없으면 **키를 비워 둔다**(미확정 → `applicability_unknown`). `False`는 사용자 답변·과제 레코드로만.
  2. 취약 대상: `제외|제외한다|미포함` 문맥과 같은 문장이면 건너뛴다. 근거 문장을 `profile["evidence"][field]`에 저장해 화면에서 "이 문장 때문에 이렇게 판단했습니다"를 보여 준다.
  3. 연구 유형: `검체`만으로 `specimen`을 확정하지 말고 `unknown` 유지 + 질문.
  4. 추정 대상 본문을 전체 문서로 넓힌다.
- 완료 기준: 위 표 3건이 각각 `drug` 미확정 / `vulnerable` 없음 / `study_type=unknown`.

## 4. C. 오탐과 중복 감점

### F-08 약물이 둘 이상이면 내용이 같아도 Critical 불일치가 뜬다

- 위치: `qc/compare.py:34-45`, `qc/checks.py:272-274`, `:345-360`(`SELF_*`)
- 재현: 계획서·동의서 모두 `A약은 1회 100mg…` `B약은 1회 50mg…` → `CROSS_DOSAGE critical mismatch` + `SELF_DOSAGE` 2건.
- 원인: 그룹 안의 값을 **문서 구분 없이 합집합**으로 보고 값이 2종이면 불일치로 판정한다. 문서별 값 집합이 서로 같은지는 보지 않는다. 약물 단위의 범위(`scope`)도 없다(군만 있음).
- 수정 방향:
  1. 판정 기준을 "문서별 값 집합이 서로 다른가"로 바꾼다. 모든 문서의 집합이 같으면 `match`.
  2. 용량 Fact의 `scope`에 같은 문장의 약물명(문장 주어 또는 `시험약|대조약|A약` 등)을 넣는다. 약물을 특정할 수 없고 한 문서에 값이 2종 이상이면 `needs_check: scope_unclear`.
  3. `SELF_DOSAGE`도 같은 이유로, 약물·군이 구분되지 않는 복수 값은 불일치가 아니라 확인 필요.
- 완료 기준: 위 재현 → 이슈 0건. 한쪽만 `B약 1회 25mg`이면 후보 1건.

### F-09 필수 방문과 선택 방문이 한 문장에 있으면 문서 내 불일치가 뜬다

- 위치: `qc/facts.py:205-206`
- 재현: `방문 횟수는 총 6회이며, 필요 시 추가 방문은 2회이다.` → `SELF_VISITS`(6회/2회).
- 원인: 필수/선택 판단을 **문장 전체**로 한다. 같은 문장의 두 값이 모두 `visits_optional`이 된다.
- 수정 방향: 매치 위치 앞 15자 정도의 **근접 문맥**으로 판단한다(`필요 시 추가 방문은 2회`의 2회만 선택). 군·기관·분석 인원 판단(`_with_scope`의 `line` 기반 분기 전부)에도 같은 문제가 있으므로 함께 고친다.
- 완료 기준: 위 재현 → `visits_required=6`, `visits_optional=2`, 이슈 0건.

### F-10 개정이력 판별이 번호·제목 형식에 따라 틀린다

- 위치: `qc/facts.py:48-61`(`versions_in_body`)
- 재현 1(오탐): `버전: v3.0` / `개정 이력` / `1. 최초 작성 v1.0` / `2. 용량 변경 v2.0` → `VERSION_INCONSISTENT`(v1, v2, v3). 이력 구간 종료 조건 `^\d+[.)]\s*[가-힣]`이 **이력의 번호 행**에도 맞아서 이력이 즉시 끝난다.
- 재현 2(미탐): 파일명 `Protocol_v3.0`, 본문 `개정 이력` / `v1.0 최초` / `연구 목적` / `본 문서 버전: v2.0` → 이슈 0건. 번호 없는 제목(`연구 목적`, `Ⅰ. 개요`, `제1장`)에서는 이력이 끝나지 않아 뒤의 현재 버전을 전부 건너뛴다.
- 수정 방향: 이력 구간을 `structure.split_sections()`의 **절 단위**로 정한다(이력 제목의 절 끝까지만 제외). 이력 구간 안에서는 "버전 + 날짜/사유" 형태의 행만 이력으로 보고, 표를 평문으로 푼 행도 처리한다. 계획 T-12의 위치 구분(`scope.where = cover|header|footer|body`)과 `버전 의미 충돌` 플래그는 미구현이므로 함께 추가.
- 완료 기준: 재현 1 → 이슈 0건, 재현 2 → `VERSION_MISMATCH` Critical 후보.

### F-11 과제 입력값 대조(R00)와 문서 간 대조가 같은 사실을 3중으로 집계한다

- 위치: `qc/checks.py:246-260`(RECORD 분기), `:264-292`(비교 분기)
- 재현: 과제 120명, 계획서 100명, 동의서 80명 → `RECORD_SUBJECTS` 2건(각 Critical) + `CROSS_SUBJECTS` 1건(Major). 모두 확정하면 63점. 한 가지 사실(대상자 수)의 문제다.
- 원인: RECORD 이슈에 `group`이 없고 문서마다 1건씩 만든다. RECORD 분기의 `continue`는 첫 번째 루프만 건너뛰므로 두 번째 루프가 같은 키를 다시 비교한다. 등급도 `criteria.yaml: cross_fields`(Critical)와 `rules.yaml`(E02 Major)이 달라 같은 필드가 두 등급으로 나온다.
- 수정 방향:
  1. RECORD 이슈를 필드당 1건으로 합치고(`locations`에 문서별 값), `group`을 문서 간 이슈와 같은 규칙으로 만들어 `group_issues`가 하나로 묶게 한다. 주 이슈는 문서 간 이슈, 과제 입력값은 `locations`의 한 줄로.
  2. 등급의 단일 출처를 `rules.yaml`로 통일하고 `criteria.yaml: cross_fields`에서 `severity`를 제거(라벨만 유지).
- 완료 기준: 위 재현 → 고유 이슈 1건(Major), 확정 시 93점.
