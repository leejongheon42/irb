# 기관 양식 (병원별 양식 대응)

병원마다 IRB 신청서 항목, 과제번호 체계, 서약서 종류가 다르다. 이 시스템은 코드를 고치지 않고 아래 네 가지로 기관 차이를 흡수한다.

| 기능 | 화면 | 권한 |
|---|---|---|
| 기관 프로필 (기관명·위원회 명칭·과제번호 형식·통지서 하단 문구·사무국 연락처) | `/admin/profile` | 관리자·간사 |
| 과제 신청서 기관 추가 항목 (양식 스키마) | `/admin/forms` → 신청서 "8. 기관 추가 항목" | 정의: 관리자·간사 / 입력: 연구진 |
| 웹 작성 서식 (이해상충 공개서·보안서약서 등을 브라우저에서 작성·전자서명) | `/protocols/{id}/online-forms` | 작성: 연구진 / 열람: 사무국·배정 위원 |
| 양식 팩 (프로필+양식 묶음 YAML 가져오기/내보내기) | `/admin/forms` | 관리자·간사 |

## 1. 기관 프로필

- 단일 행(`institution_profile`). 처음 조회할 때 환경설정(`IRB_INSTITUTION_NAME`, `IRB_IRB_NAME`) 값으로 만들어진다.
- 화면 템플릿의 `settings.institution_name`/`settings.irb_name`은 프로필 값을 우선 사용한다(`forms.profile.SettingsView`). 추가로 `settings.letter_footer`, `settings.irb_contact`, `settings.protocol_no_format`을 쓸 수 있다. 값은 30초 캐시되며 저장 시 즉시 갱신된다(다중 프로세스 배포에서는 최대 30초 지연).
- **과제번호 형식** 토큰: `{YYYY}` `{YY}` `{SEQ}` `{SEQ:n}`. 예) `IRB-{YYYY}-{SEQ:4}` → IRB-2026-0001, `{YY}-{SEQ:3}-C` → 26-001-C.
  - 일련번호 = 같은 형식·같은 연도 기존 번호의 최댓값 + 1(결번이 있어도 중복 없음). 기존 `IRB-YYYY-NNNN` 데이터와 그대로 이어진다.
  - 형식을 바꾸면 새 형식 기준 1번부터. 이미 부여된 번호는 바뀌지 않는다. `{SEQ}`는 정확히 1개 필요.

## 2. 과제 신청서 기관 추가 항목

`FormDefinition(kind="protocol")`의 활성 버전이 신청서 "8. 기관 추가 항목"으로 렌더링되고, 값은 `Protocol.custom_fields`(JSON)에 저장된다.

```yaml
sections:
  - title: 연구비 및 행정 정보
    fields:
      - key: grant_number          # 영문 소문자·숫자·밑줄, 기본 과제 항목명(title 등) 사용 불가
        label: 연구비 과제번호
        type: text                 # text|textarea|number|date|select|multiselect|checkbox|yesno
        required: true
        show_when: {field: funding_source}       # 기본 과제 항목도 참조 가능, equals 생략 = 값이 있으면
      - key: fee_paid
        label: 심의비 납부
        type: yesno
        show_when: {field: irb_fee_category, equals: industry}
      - key: center
        label: 소속 연구센터
        type: select
        material: true             # 변경 대비표에서 핵심 변경(★)
        options: [{value: a, label: 임상의학연구소}, {value: b, label: 의생명연구원}]
      - {key: rows, label: 추출 행 수, type: number, min: 1, max: 1000000}
```

- **버전 관리**: 저장은 항상 새 버전, kind별 활성 1개. 과거 버전은 남고 다시 활성화할 수 있다.
- **사전검토**: 표시 조건이 참인 필수 항목 미입력 → `CUSTOM_REQUIRED`(필수 보완, field=`custom__<key>`), 범위·선택지 오류 → `CUSTOM_INVALID`(보완 권고).
- **스냅샷·변경 대비표**: 제출 스냅샷에 `custom_fields`와 그 시점의 라벨·선택지(`custom_field_meta`)가 함께 저장되어, 양식이 바뀐 뒤에도 과거 제출본과 변경 대비표("[기관] 라벨")를 그대로 해석한다.
- 현재 양식에서 빠진 항목의 기존 값은 수정 저장 시 지워지지 않고 보존된다.
- 다른 모듈은 `forms.schema.active_protocol_fields(db) -> list[FieldDef]`(key, label, type, required, options, help, section …)로 활성 항목을 얻는다.

## 3. 웹 작성 서식

`FormDefinition(kind="online:<doc_type>")`. 스키마 최상위에 다음을 추가한다.

| 키 | 의미 |
|---|---|
| `label` | 표시 이름(필수). doc_type이 서류 카탈로그에 없을 때도 이 이름을 쓴다 |
| `per_member` | true = 연구책임자·공동연구자 **각자** 1부, false = 과제당 1부 |
| `signer: pi` | 과제 단위 서식을 연구책임자만 작성 |
| `required` | 기관 필수 서식(미제출 시 `ONLINE_FORM_REQUIRED` 필수 보완) |
| `intro`, `pledge` | 안내문, 서약문 |
| 항목 `prefill` | `user.full_name`, `user.department`, `pi.full_name`, `protocol.title`, `today` 등 자동 채움 |

흐름: 작성 → 임시저장(draft) → **서약 동의 + 비밀번호 재인증 전자서명**(`esign.sign`) → 인쇄용 HTML을 렌더링해 `Document`로 첨부(파일명 `<라벨>(웹작성)[_성명]_v<회차>.html`, doc_type = 서식 코드) → 서류 체크리스트 충족.

- 재제출하면 응답 버전과 문서 버전이 올라가고, 서명 해시가 새로 기록된다. 응답(`online_form_responses`)에는 서명 ID·첨부 문서 ID·사용한 양식 버전이 남는다.
- **개인별 서식 충족 규칙**: 연구진 **전원**이 제출해야 해당 서류가 체크리스트에서 "제출"로 인정된다. 일부만 제출된 동안에는 체크리스트에서 제외되고 `ONLINE_FORM_INCOMPLETE`(보완 권고)에 미제출 연구진 이름이 표시된다. 같은 종류 서류를 파일로 업로드했다면(종이 서식 스캔 등) 업로드본이 우선 인정된다.
- 작성 가능 상태: 작성중·보완요청·변경작성. 사무국(간사·위원장)과 배정 위원은 열람·인쇄본 조회만 가능하다.

## 4. 양식 팩

```yaml
pack: sample_hospital_b
name: △△의료원 양식 팩
profile: {institution_name: △△의료원, protocol_no_format: "{YY}-{SEQ:3}-B"}   # 선택
forms:
  - {kind: protocol, name: ..., schema: {...}}
  - {kind: online:coi, name: ..., schema: {...}}
```

- 기본 제공: `forms/packs/default.yaml`(예시 추가 항목 5개 — 모두 선택 입력이라 기존 동작을 바꾸지 않음 — 와 웹 서식 3종), `forms/packs/sample_hospital_b.yaml`(다른 번호 체계, 필수 항목, 필수 웹 서식).
- 가져오기: 전체 검증 후 각 양식을 새 버전으로 저장(선택적으로 활성화·프로필 적용). 오류가 하나라도 있으면 아무것도 바뀌지 않는다.
- 내보내기: 현재 활성 양식 + 기관 프로필을 YAML로 다운로드 → 다른 병원·다른 서버에 그대로 가져오기.
- 초기 로드: 양식 정의가 하나도 없으면 `seed_forms(db)`가 기본 팩을 활성화한다(멱등). `/admin/forms`, 신청서 화면, 웹 서식 화면 진입 시 자동 실행된다.
