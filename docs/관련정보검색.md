# 관련 정보 검색 (지식베이스 · 근거 인용 질의응답)

심의 과정에서 필요한 근거(법령·지침 요약, 기관 SOP, 검토 의견별 보완 가이드, FAQ, 과거 과제·심의 선례)를 한 곳에 색인하고,
검색·질의응답·사전검토 화면에서 자동으로 찾아 보여 줍니다.

## 화면

| 경로 | 대상 | 기능 |
|---|---|---|
| `/knowledge` | 로그인 사용자 | 키워드·조문 검색, 유형 필터(패싯), 질의어 하이라이트, 원문 링크 |
| `/knowledge/ask` | 로그인 사용자 | 질문하면 근거를 인용해 답함(AI 근거 인용 / 자동 발췌) |
| `/knowledge/source/{id}` | 권한에 따라 | 지식 문서 전체 보기 |
| `/admin/knowledge` | 간사·위원장·관리자 | SOP·지침 업로드(TXT·MD, PDF·DOCX·HWPX·HWP는 문서 인식 모듈 필요)·붙여넣기, 사용/중지, 재색인, 삭제, 내장 지식 갱신, 선례 재색인 |

API(로그인 필요): `GET /api/knowledge/search?q=&k=&kind=`, `POST /api/knowledge/answer {"question", "k"}`.

## 지식의 종류

| kind | 내용 | 출처 |
|---|---|---|
| `law` | 생명윤리법 제11·12·14·15·16·18조, 시행규칙 제13조, 개인정보 보호법 제23·24·24조의2·28조의2~28조의8·29조 요약 | 내장(`knowledge/builtin/laws.yaml`) |
| `guideline` | 보건의료데이터 활용 가이드라인, 가명정보 처리 가이드라인(비정형), Five Safes, 결과 반출 소규모 셀, 평가·인증, 다기관 | 내장(`guidelines.yaml`) |
| `finding_guide` | 자동 사전검토 검토 의견 코드별 보완 방법·작성 예시·근거 | 내장(`finding_guides.yaml`) |
| `faq` | 연구자 자주 묻는 질문 15개 | 내장(`faq.yaml`) |
| `sop`·`uploaded` 등 | 기관이 등록한 문서 | `/admin/knowledge` |
| `protocol`·`decision` | 제출된 과제 요약과 심의 결정(조건·의견·주요 검토 의견) | 자동 색인 |

법령·지침은 **요약본**이며 제목에 "요약 — 원문 확인 필요"를 붙이고 국가법령정보센터 등 원문 링크를 둡니다.
세부 항 번호처럼 개정으로 바뀔 수 있는 내용은 단정하지 않았습니다. 내장 YAML의 `version`을 올리면 다음 실행 시(또는
"내장 지식 갱신") 바뀐 문서만 갱신됩니다(`seed_knowledge(db)` 멱등). 첫 검색 때도 자동 적재됩니다.

## 검색 방식

- **토크나이저**: 형태소 분석기 없이 한글은 문자 2-gram, 영문·숫자는 단어 단위(`RRN_COLLECTION`은 전체와 부분 모두).
  문장 어미·질문 표현(예: "니다", "해야", "나요")은 제외합니다.
- **조문 정규화**: `제28조의2` · `28조의2` · `제 28 조의 2` → 같은 토큰. `제16조제3항` → `제16조` + `제16조제3항` 토큰.
  조문 질의는 해당 조문 문서가 최상위에 오도록 테스트로 보장합니다.
- **BM25**(k1·b·제목 가중치는 규칙 세트 `knowledge:`에서 조정), 문서별 대표 구간 1개만 표시.
- **캐시**: DB별 메모리 색인. 청크·출처 수와 최근 변경 시각이 바뀌면 다시 만듭니다.
- **하이라이트**: 원문을 escape한 뒤 `<mark>`만 삽입합니다(사용자 입력이 HTML로 해석되지 않음).
- **청크 분할**: 마크다운 제목, 장·절·조문(`제1조(목적)`), `1.`/`1.2`/`가.` 번호, `【】` 제목 경계로 나누고 900자 넘는 구간은 문단·문장 단위로 다시 나눕니다.

## 노출 정책(선례)

- 정책 지식(법령·지침·SOP·FAQ·가이드·등록 문서)은 모든 로그인 사용자에게 공개합니다.
- 과거 과제·심의 선례는 규칙 세트 `knowledge.precedent_roles`(기본: 간사·위원장·관리자·심의위원)만 전체를 봅니다.
- 그 외 사용자(연구자·데이터관리자)는 **자신이 열람할 수 있는 과제(`workflow.can_view`)의 선례만** 보며,
  타 과제는 검색 결과·문서 보기·건수 통계 어디에서도 존재 여부를 드러내지 않습니다(요약 공개도 하지 않음).
  타 과제 선례를 요약 형태로 공개하려면 별도 비식별·승인 절차가 필요하다고 보고 기본값에서 제외했습니다.
- 내부 호출(`user=None`)은 필터 없이 검색하므로 연구자에게 보여줄 결과를 만들 때는 반드시 `user`를 넘깁니다.
  `answer(user=None)`은 정책 지식만 사용합니다.

## 근거 인용 질의응답

1. 질문의 개인정보(주민번호·카드·전화·이메일·여권·IP·상세주소, "OOO 환자" 형태 이름)를 **검색·AI 전송·기록 전에 마스킹**하고 사용자에게 알립니다.
2. BM25로 근거 청크(최대 6개)를 찾습니다.
3. AI가 켜져 있으면(`irb_automation.ai.client.ai_enabled()`), 각 청크를 `text_document_block(..., citations=True)` 문서 블록으로 넣어
   `create_message`를 호출합니다(Citations와 구조화 출력은 함께 쓸 수 없으므로 `output_schema` 없이 호출).
   응답 text 블록의 `citations[]`(`cited_text`, `document_index`)를 검색 결과로 되짚어 `[n]` 표시와 인용 카드를 만듭니다.
4. AI 모듈이 없거나, 꺼져 있거나, 오류·거절이면 **추출형 답변**(최상위 근거 + 법령·지침 근거 + 다음 근거의 핵심 문장 발췌와 인용)으로 대체합니다.
5. 질의는 `KnowledgeQuery`(마스킹된 질문, 방식, 결과 수)와 감사 로그(`knowledge_search`/`knowledge_answer`)에 남습니다.

## 다른 구성 요소와의 인터페이스 (`irb_automation/knowledge/service.py`)

```python
search(db, query, k=5, kinds=None, user=None) -> list[dict]
# 키: source_id, chunk_id, kind, kind_label, title, ref, heading, snippet, highlight(Markup), score, url, view_url, external_url
related_for_findings(db, findings, k=3) -> dict[str, list[dict]]   # 검토 의견 code → 근거(해당 코드 보완 가이드가 1순위)
similar_protocols(db, protocol, k=5, user=None) -> list[dict]      # protocol_id, protocol_no, title, status, decision, review_type, score, url
answer(db, question, k=6, user=None) -> dict                       # answer, citations[{title, ref, cited_text, source_id, ...}], mode, warnings, hits
```

화면에서 쓰는 매크로(`templates/knowledge/_related.html`, 독립 import 가능):

```jinja
{% import "knowledge/_related.html" as kn %}
{{ kn.findings_related(result.findings, related) }}   {# 사전검토 검토 의견별 근거 #}
{{ kn.related_panel(hits) }}
{{ kn.similar_panel(similar) }}                       {# 유사 과제(선례) 표 #}
```

## 모델

`KnowledgeSource`(kind, title, ref, url, version, active, file_path, sha256, meta, created_by/at, key),
`KnowledgeChunk`(source_id, seq, heading, text, length), `KnowledgeQuery`(user_id, question, mode, result_count, created_at).
업로드 원본은 `data/knowledge/`에 저장하고 SHA-256을 기록합니다.

## 한계

- 의미 검색(임베딩)이 아니라 어휘 기반 검색이라 동의어(예: "면제" ↔ "생략")는 놓칠 수 있습니다. FAQ·가이드에 표현을 추가해 보완합니다.
- 색인은 프로세스 메모리에 있으므로 다중 프로세스 배포에서는 프로세스마다 따로 만듭니다(변경 표식으로 일관성 유지).
- 법령 요약은 개정을 자동 반영하지 않습니다. 개정 시 YAML을 고치고 `version`을 올리십시오.
