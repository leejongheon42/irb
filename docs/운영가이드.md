# 운영 가이드 (v4.0 연구자용)

이 시스템은 연구자가 IRB 제출 서류를 자동으로 완성·점검하는 도구입니다. 심의는 병원 e-IRB에서 진행합니다.
화면별 설명은 [기능_및_화면_안내.md](기능_및_화면_안내.md), 점검 기준은 [서류점검.md](서류점검.md)를 참고하십시오.

## 1. 역할

| 역할 | 하는 일 |
|---|---|
| 연구자 | 과제 정보 입력·가져오기, 서류 자동 완성·점검·교정, e-IRB 제출 기록, 보완 요청 대응, 결과·변경·지속·종료 관리 |
| 관리자(연구지원 담당) | 기관 프로필·양식·서식 등록, 점검 기준·사전점검 규칙 조정, 지식(SOP) 관리, AI 설정, 사용자 관리. 기관 전체 과제 열람 |

## 2. 처음 도입할 때 (관리자)

1. **기관 프로필**: 기관명, IRB 명칭과 연락처를 입력합니다. 연락처는 자동 작성 동의서의 IRB 연락처에 들어갑니다.
2. **기관 서식**: 병원 IRB 홈페이지의 양식(DOCX·HWPX)에 `{{연구제목}}` 같은 자리표시자를 넣어 업로드하고 매핑한 뒤 활성화합니다. HWP는 HWPX로 저장해 올립니다.
3. **기관 양식**: 병원 신청서에만 있는 항목을 추가하고, 웹 작성 서식(이해상충·서약서 등)을 설정합니다.
4. **점검 기준**: `qc/criteria.yaml`을 복사해 기관 필수 기재사항·용어 표준·오탈자를 추가하고 `IRB_QC_CRITERIA_PATH`로 지정합니다.
5. **지식**: 기관 SOP·FAQ를 업로드합니다(관련 근거 검색·보완 대응에 사용).
6. **LibreOffice**: 설치하면 기본 서식이 편집 가능한 DOCX로 만들어집니다.

## 2-1. 연구자 표준 흐름

1. **과제 정보 입력**: 새 과제를 만들거나, 다른 병원 양식의 기존 계획서를 올려 AI 인식으로 초안을 만듭니다.
2. **제출 서류 패키지 → 자동 완성 실행**: 빈 서술 항목 초안 작성, 필요 서류 자동 작성, 전체 서류 점검이 한 번에 진행됩니다.
3. **점검 결과 확인**
   - Critical부터 해결합니다.
   - 자동 교정 가능한 항목은 선택해서 교정합니다(변경 추적본·수정 완료본).
   - 내용을 새로 써야 하는 항목은 과제 정보를 수정한 뒤 *다시 작성*합니다.
4. **개인 서류 업로드**: 이력서, 교육 이수증 등을 올립니다.
5. **e-IRB 업로드용 ZIP**을 받아 병원 e-IRB에 올리고, 과제 화면에서 **제출 기록**을 남깁니다(접수번호 선택 입력).
6. **결과 처리**
   - 결과 통지를 받으면 결과를 입력합니다(승인 만료일, IRB 승인번호).
   - 보완 요청을 받으면 요청문을 붙여넣습니다. 이후 *보완 대응*에서 답변을 작성하고 보완 답변서를 자동 작성한 뒤, 재제출 패키지를 점검하고 재제출을 기록합니다.
7. **사후 관리**
   - 만료 60·30·7일 전 알림이 오면 *지속심의* 패키지를 준비합니다.
   - 연구 종료 시 *종료보고*를 합니다.
   - 변경이 필요하면 *변경 준비 시작*을 누릅니다. 변경 대비표가 자동 작성됩니다.

## 2-2. AI 사용 원칙
- 기본값은 꺼짐(`IRB_AI_ENABLED=false`)이며 외부 전송이 없습니다. 꺼져 있어도 규칙 기반 초안·점검·교정은 모두 동작합니다.
- 켜기 전에 기관 개인정보보호 담당자와 전송 범위를 협의하십시오(서류 종류 허용 목록 `IRB_AI_DOC_TYPES_ALLOWED`).
- 전송 전 개인정보 패턴을 마스킹하고, 전송 내역(목적·해시·크기)을 감사 로그에 남깁니다. 원본 의료데이터(가명처리 대상 CSV)는 AI로 보내지 않습니다.
- AI 초안·점검 결과는 참고용이며, 연구자가 검토해야 합니다.

## 2-3. 서류 점검 기준 운영
- 같은 보완 요청이 반복되면 점검 기준에 추가합니다(예: 기관 필수 문구, 금지 표현). IRB 결과와 보완 요청은 지식 검색의 '과거 사례'로도 쌓입니다.
- 점수 기준(`scoring`)은 기관 내부 목표에 맞게 조정할 수 있습니다. Critical 0건은 유지하는 것을 권장합니다.

## 3. 사전점검 규칙 세트(YAML) 수정

`irb_automation/rules/default_ruleset.yaml`을 복사해 기관용 파일을 만들고 `IRB_RULESET_PATH`로 지정합니다. 파일을 저장하면 다음 사전검토부터 반영되며(서버 재시작 불필요), 각 결과에 `버전#해시`가 기록되어 어떤 규칙으로 판정했는지 추적할 수 있습니다.

| 항목 | 키 | 예시 |
|---|---|---|
| 법령 문구 | `legal_basis` | 개정 시 조문 문구 갱신 |
| 위험도 구간 | `risk_levels` | 최소위험 상한을 19 → 15로 |
| 정규심의 기준 | `review_type.expedited_max_score` | 44점 초과 시 정규심의 |
| 가명정보 면제 허용 | `review_type.exemption.allow_pseudonymized` | 기관이 가명정보 연구 면제를 불허하면 `false` |
| 면제 제외 범주 | `review_type.exemption.excluded_sensitive / excluded_vulnerable` | 소아 후향 연구 면제를 허용하려면 `children` 제거 |
| 정규심의 유발 조합 | `review_type.full_board_triggers` | 식별정보 + 특정 민감정보 |
| 요인별 가중치 | `risk_weights`, `catalogs.*.weight` | 외부 클라우드 저장 가중치 상향 |
| 카탈로그 | `catalogs.*` | 기관 데이터 출처(예: 바이오뱅크) 추가 |
| 필수 서류 | `required_documents` | `{doc: budget, when: [funded]}` |
| 가명처리 기준 | `deid_policy` | `k_threshold: 10`, `age_band_years: 10` |

`required_documents.when`에 쓸 수 있는 조건: `exempt`, `not_exempt`, `consent_obtain`, `consent_waiver`, `not_anonymized`, `identifiable`, `external_transfer`, `data_linkage`, `funded`, `coi`, `ai_ml`, `kind_initial`, `kind_continuing`, `kind_final_report` (정의되지 않은 조건은 오류로 처리됩니다).

## 4. 가명처리 도구 사용 원칙

- **원본 취급**: 원본 추출 파일은 기관 규정에 따라 허가된 원내 환경에서만 처리하고, 처리 후 *원본 파기*를 실행합니다(파기 기록이 남습니다).
- **추가정보 분리 보관**: HMAC 키(`IRB_PSEUDONYM_SECRET`)와 일련번호 매핑표(`data/keys/mappings`)는 가명정보와 분리된 위치·권한으로 보관합니다(개인정보 보호법 제28조의4).
- **과제별 가명**: 같은 환자라도 과제마다 다른 가명이 생성되어 과제 간 무단 결합을 막습니다.
- **날짜 이동**: 대상자 식별 컬럼을 지정하면 대상자별로 동일한 이동량을 적용해 입원–퇴원 간격 등이 보존됩니다.
- **k-익명성 미달 시**: 연령 구간 확대(5→10세), 주소 범주 상향(시군구→시도), 날짜 연·월 범주화, 레코드 삭제 순으로 조정합니다.
- **결과 공표**: 소규모 셀(5명 미만) 억제는 연구자 책임으로 안내합니다.

## 5. 백업과 감사

- 백업 대상: DB(`IRB_DATABASE_URL`), `data/uploads`(제출 서류), `data/deid`(가명처리 결과), `data/keys`(별도 보안 백업)
- 정기 점검: `python -m irb_automation verify-audit` — 해시 체인 불일치 시 해당 로그 번호를 출력하고 종료코드 2를 반환합니다.
- 스케줄러: 웹 서버에 내장(1시간 주기). 다중 인스턴스로 운영하면 `IRB_SCHEDULER_ENABLED=false`로 끄고 cron에서 `run-scheduler`를 하루 1회 이상 실행하십시오.

## 6. 알려진 한계와 확장 포인트

- 인증은 자체 계정 방식입니다. 병원 SSO(LDAP/SAML/OIDC)는 `web/deps.py`의 `current_user_optional`을 교체해 연동합니다.
- 알림은 시스템 내부 알림입니다. 메일/메신저 발송은 `notifications.notify`에 발송 로직을 추가하십시오.
- 가명처리 입력은 CSV입니다. 대용량(수백만 행)은 CDW 측에서 분할 추출하거나 배치 처리로 확장하십시오. DICOM 영상 비식별화는 별도 도구(예: 헤더 태그 처리기)와 병행해야 합니다.
- 한글 성명 추정은 휴리스틱이므로 자유기술 스크러빙 결과는 표본 검수를 권장합니다.
- SQLite는 단일 서버용입니다. 동시 사용자가 많으면 PostgreSQL로 전환하십시오.
